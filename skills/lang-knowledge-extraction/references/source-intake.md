# 素材接入与证据契约

素材可以来自文字、聊天截图、录音、会议转写、文档、文件或链接。来源形式不同，最终都要先变成同一份可追溯证据包，再进入知识萃取。

## 证据包最小结构

```yaml
source_id: <稳定标识；优先沿用平台或文件身份>
source_type: <text|chat|screenshot|audio|transcript|document|file|link>
title: <已有标题；没有就写简短描述>
original_ref: <附件、路径、消息、URL或平台位置>
captured_at: <来源已有时间；未知则留空>
participants: []
content: <可分析正文、OCR或转写>
locators: <页码、消息时间、截图区域、音频时间戳等>
completeness: <complete|partial|unknown>
attribution_status: <verified|inferred|unknown>
sensitivity: <private|team|public_candidate|unknown>
transformations: []
```

`transformations` 记录 OCR、转写、清洗、说话人修正或人工补充。它让后续使用者知道哪些是原始证据，哪些经过机器处理。

## 聊天截图

1. 读取图片中的消息顺序、可见说话人、时间和文字；原图继续作为证据，OCR 文本只是派生结果。
2. 截图裁掉了上文、说话人或时间时，标 `partial` 或 `unknown`。只对画面内有充分支持的命题形成候选；需要上下文才能成立的判断进入 `needs_review`。
3. 多张连续截图先按时间和重叠消息排序去重。无法确认顺序时不拼造对话。
4. 区分用户本人、他人和 AI 的表达。AI 提议只有在用户明确采用、修改或确认后，才能作为用户的已采用知识；否则保留真实归属。
5. 截图含手机号、客户姓名、金额、健康、人事或其他敏感信息时，继承更严格的可见范围；不因萃取成一句话就自动脱敏成功。

## 录音与转写

1. 宿主有可用转写能力时，先生成带时间戳的完整转写；没有时请求用户提供转写稿，不假装听过音频。
2. 说话人分离不可靠时标出不确定区间。归属会影响知识所有者时，先让用户确认关键片段。
3. 自动修正口头语、错别字或标点不能改变原意；重要数字、专名和否定词回听或要求核验。
4. 只给片段也可以进入候选预览，但必须标 `partial`。涉及重要决策、对他人评价或公开金句时，优先补齐前后文。

## 文档、文件与链接

- 已附完整文件时直接读取可用正文，并保留页码、段落或单元格位置。
- 只有链接时，使用当前宿主已授权的浏览器或连接器读取；访问失败就说明需要上传、导出或粘贴正文。
- 在线内容可能变化时保存访问时间和稳定位置。不要只保存一段无来源摘要。
- 表格、PPT、PDF 或图片型文档要记录抽取方式；结构丢失会改变含义时，回到原文件核验。

## 用户随手输入

用户直接说的一段想法也可以作为来源。记录为 `source_type: text`，作者是当前用户，位置是当前会话。若这段话本身仍在试探、提问或否定某个观点，不要误判为已采用判断。

## 完整度与行动

| 状态 | 可以做什么 |
|---|---|
| `complete` | 正常进入已启用库的准入与去重 |
| `partial` | 形成有边界的候选；只有当前片段独立支持时才允许确认写入 |
| `unknown` | 先做预览或请求补充，不写成已确认知识 |

低风险素材不因缺一个时间戳全部阻断；但作者、核心语义或上下文缺口会改变结论时，必须停在 `needs_review`。
