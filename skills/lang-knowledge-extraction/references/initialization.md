# 初始化契约

初始化的目标是让用户在一次短对话后，拥有一个能接收真实素材、能审核、能回查的最小萃取闭环。不要先教用户理解全部配置，也不要要求他一上来搭四库、分类树和自动化。

## 初始化状态机

```text
未配置 → 盘点现状 → 生成初始化方案 → 用户确认外部变更 → 建立／映射 → 验证 → 可用
                         ↘ 无写入工具：生成配置草稿与导入模板 → 部分可用
```

重复运行必须幂等：复用已有配置、库和字段；缺什么补什么。不得因名称相同就覆盖或另建第二套。

## 先自动发现

在提问前先只读检查：

- 是否已有 `.knowledge-extraction/config.yaml`；
- 用户是否已经给出飞书、钉钉、企微、Excel、数据库或其他知识库入口；
- 载体中是否已有概念、判断、案例、金句或类似表／工作表；
- 当前宿主能否读取截图、转写音频、访问链接、读取／写入目标载体；
- 是否存在现有数据、团队成员、权限或敏感内容。

能从当前材料确定的内容不要再问。只有会改变长期权威源、共享边界或数据结构的选择才追问。

## 学员只需完成四个决定

采用一轮一个小问题的方式推进；用户愿意时也可以一次回复四项。

### 1. 谁使用

确认是个人使用还是团队使用，以及谁负责最终审核。团队模式还要确认默认可见范围；不知道时使用 `private`，不自动邀请成员。

### 2. 先开哪些库

默认推荐 `starter`：

| 档位 | 启用内容 | 适合情况 |
|---|---|---|
| `starter` | 概念库、判断库 | 首次使用，先学会把零散经验变成可复用认知 |
| `growth` | starter + 案例库 | 已经反复需要用真实经历证明、修正或讲清判断 |
| `advanced` | growth + 金句库 + 可选自动化治理 | 已有稳定审核习惯，并持续用于内容、课程或团队知识运营 |

这是推荐起点，不是永久限制。用户明确只要一个库时也允许；不要为满足档位强制创建空库。

### 3. 放在哪里

不要先问产品名，先问真实使用条件：是否多人协作、是否需要手机访问、是否需要关系字段、是否已有平台、是否愿意维护数据库。

默认选择顺序：

1. 已有且用户每天会打开的可维护载体；
2. 团队协作或需要关联时，优先结构化在线表；
3. 单人、低频、没有在线连接器时，优先本地工作簿；
4. 文档表格可作为轻量起点，但要接受并发、去重和关联能力较弱；
5. 自有数据库只在用户已有维护能力、备份和访问接口时启用。

具体映射见 `storage-contract.md`。飞书、钉钉、企微、本地 Excel 和自有数据库都是示例，不是硬编码白名单。

### 4. 先预览还是直接进待审核

首次默认 `preview_then_confirm`。只有用户已经连续使用并明确接受候选直接进入待审核区时，才改为 `direct_pending`。任何模式都不能让 AI 自动写成已确认。

## 不需要学员先决定的项目

以下项目使用安全默认值，等真实使用暴露需求再调整：

- 分类体系：先为空，从已确认知识和检索行为中形成；
- 每轮数量：保留少量真正会影响未来判断的候选，不凑数；
- 来源类型：文字、聊天、截图、录音、文件和链接均可接入，按实际工具决定；
- 概念层级、关联网络、定时任务、审核预算、保密分库和跨批次晋升：默认关闭；
- 历史数据迁移：不属于首次初始化，另做只读盘点和迁移方案。

## 配置契约

把配置写到用户确认的知识根目录 `.knowledge-extraction/config.yaml`；单一用户无项目根时，可使用用户目录下同一路径。使用 [../assets/starter-config.example.yaml](../assets/starter-config.example.yaml) 作为字段模板，不把示例占位符当成真实值。

必须配置：

- `profile` 与 `enabled_libraries`；
- `owner.scope`、`review_owner`、默认可见范围；
- `storage.mode`、`platform`、唯一权威位置和各库映射；
- `review.write_mode` 与状态；
- `source_intake.provenance_required`；
- `maintenance.dedupe_scope` 与备份责任。

连接器账号和秘密只记录“从哪里读取”，不把真实密码、token、cookie 或数据库密钥写进配置。

## 建立前 dry-run

执行外部写入前给用户一个短方案：

```text
将启用：概念库、判断库
权威载体：{平台与位置}
将复用：{已有对象}
将新建／补齐：{对象或字段}
默认审核：先预览，确认后写
默认可见：私有
暂不启用：案例、金句、自动化、保密分库
```

新建共享空间、邀请成员、改权限、覆盖字段、迁移旧数据或替换权威源都必须单独确认。创建本地新配置和用户明确要求的新空模板属于初始化范围，但仍先展示目标路径。

## 最小验收

初始化完成必须同时满足：

1. 配置可被下一次运行唯一找到；
2. 所有启用库都有映射且字段满足最小契约；
3. 权威源唯一，旧载体若存在已明确为历史、待迁移或仍是权威；
4. 当前身份至少能读取结构；声称可写时还要验证写入能力；
5. 审核人、默认可见范围和状态流明确；
6. 用一条不落库的示例完成“素材 → 证据包 → 候选预览 → 去重检查”演练；
7. 无法验证的外部能力列入 `needs_setup`，不能报告全部完成。

初始化回报保持简短：当前能用什么、知识写到哪里、第一次可以给什么素材、还有什么未接通。
