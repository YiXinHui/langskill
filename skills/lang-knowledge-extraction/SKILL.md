# 归纳式经验萃取师

这个 Skill 帮用户把零散素材变成以后能再次调用的知识。先让最小闭环跑起来，再随着真实使用增加案例、金句、自动化和更复杂的治理。

## 启动路由

每次运行先查找有效配置，顺序如下：

1. 用户当前明确指定的配置文件；
2. 当前工作目录或向上最近的 `.knowledge-extraction/config.yaml`；
3. 用户目录下 `.knowledge-extraction/config.yaml`。

不得在已安装的 Skill 目录中保存个人配置、账号、密钥或真实库地址。找到多份配置且无法确定当前权威源时，只问用户选择哪一份，不合并配置。

- 配置不存在、字段不完整，或用户明确说“初始化／重新配置／换载体”：完整读取并执行 [references/initialization.md](references/initialization.md)。
- 处理截图、录音、聊天、链接、文档或文件：先完整读取 [references/source-intake.md](references/source-intake.md)。
- 形成候选前：完整读取当前已启用库在 [references/library-contracts.md](references/library-contracts.md) 中的规则。
- 写入或迁移前：完整读取 [references/storage-contract.md](references/storage-contract.md)。
- 处理审核反馈、扩库或升级自动化前：完整读取 [references/review-and-growth.md](references/review-and-growth.md)。

## 默认产品状态

首次初始化默认使用 `starter`：

- 只启用 `concepts` 与 `judgments`；
- 采用 `preview_then_confirm`，候选先给用户看，确认后再写；
- 每轮只保留少量高价值候选，每类允许为零；
- 默认私有，不自动分享，不自动改权限；
- 不预设领域分类树，分类从已确认知识和真实检索需求中长出来；
- `cases`、`quotes`、定时自动化、保密分库和跨批次概念晋升保持关闭。

用户未作选择时使用这些默认值，不把一整张配置表扔给用户填写。

## 日常萃取流程

### 1. 读取配置与能力

确认当前启用的库、权威存储位置、审核人、写入模式、隐私默认值和可用读取／写入工具。配置声明的能力与实际工具不一致时，以实际可验证能力为准；继续完成可做的部分，并把不能回读或写入的步骤标为 `needs_setup`。

### 2. 建立证据包

按 `source-intake` 把素材整理为可追溯的证据包。保留来源类型、原始位置、作者／说话人、时间或画面位置、完整度、敏感度和必要的最短证据。OCR、转写和 AI 推断不能冒充原话。

### 3. 只运行已启用的库

按 `library-contracts` 独立判断每个候选。未启用的库不扫描、不生成候选，也不借其他库字段暗中积压。默认流程以判断为主轴：概念通常由已准入判断或来源中的明确稳定定义发起，普通名词、任务、事实、SOP 和漂亮句子不自动升级。

### 4. 预览、去重与确认

先与权威库做结构化和语义去重，再按配置处理：

- `preview_then_confirm`：展示候选、出处、为什么值得留和不确定点；用户确认后才写；
- `direct_pending`：只在用户已明确启用时，把通过门槛的候选写为 `pending_review`，不能直接确认；
- `preview_only`：只返回候选，不写任何载体。

用户的“沉淀一下”允许按现有配置写入；它不授权新建共享空间、改权限、覆盖已确认记录或公开内容。

### 5. 写入与回读

按 `storage-contract` 使用稳定 ID／写入键写入正确库。写后回读真实位置、核心字段、状态和关联；无法回读时不能报告 `created`。文档型载体或本地工作簿不支持真实关联时，用稳定 ID 文本引用，不伪装成数据库关系。

### 6. 返回结果

只需返回最有用的五类信息，展示格式随当前对话调整：

- `created`：确认写入且回读成功；
- `duplicates`：命中已有知识及其真实位置；
- `skipped`：不值得入库或被已有知识吸收，并说明原因；
- `needs_review`：归属、上下文、证据或冲突需要人判断；
- `needs_setup`：配置、权限、工具或载体能力尚未就绪。

## 权威优先级

1. 用户当前明确指令与确认；
2. 当前配置指定的唯一知识权威源及其真实结构；
3. 本 Skill 对来源、库准入、审核和存储的稳定契约；
4. 模板与示例。

模板只是起点，不覆盖用户已存在的字段、权限和知识资产。

## 禁止事项

- 不因追求“自动沉淀”而跳过作者归属、来源锚点、隐私和人工确认边界。
- 不把截图中的可见片段假装成完整对话，不把自动转写假装成已核对原话。
- 不自动把个人素材写进团队共享库，不自动公开，不在配置中保存密码、令牌或数据库密钥。
- 不因换载体就维护两套当前知识；迁移前明确唯一权威源和切换点。
- 不为了让四库看起来完整而强行生成案例或金句。
