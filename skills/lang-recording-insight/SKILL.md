# Recording Insight｜录音洞察

录音先做高门槛筛选，再由人决定哪些值得深挖。默认目标不是“把每段话都总结一遍”，而是建立一个低噪声候选水库。

## 两阶段边界

### 默认阶段：筛选

- 读取转写稿并识别说话人、时间戳和上下文。
- 抽取少量真正有损失价值的候选。
- 每条保留原话证据。
- 不自动写入知识库、客户档案、内容选题或任务系统。

### 深挖阶段：用户选择后展开

只有用户明确说“深挖第 N 条”“把这条整理成观点／方法”时，才对选中项做逻辑、证据、边界和应用分析。

如果用户已经明确指定要深挖的片段，可以直接进入第二阶段。

## 默认筛选流程

### 1. 读取与校验

确认输入至少包含可读文本。时间戳或说话人缺失时可以继续，但必须标明“原稿未提供”，不能伪造。

先识别：

- 录音类型：会议、访谈、课程、咨询、复盘、自言自语等；
- 关键实体：人物、组织、产品、日期、数字；
- 是否存在转写错误、说话人混淆或上下文缺口。

涉及事实归属时，以原始录音／转写为准；无法确认就保留不确定性。

### 2. 去重与聚合

同一意思被重复表达多次，只保留一条主候选，把其他位置作为补充证据。不要把重复当成更多洞察。

### 3. 按七类筛选

| 类别 | 收录标准 | 不收什么 |
|---|---|---|
| 观点／洞察 | 对“X 是什么、为何如此”的可迁移判断 | 普通常识、操作指令 |
| 共性问题 | 某类人反复可能遇到、值得继续研究的问题 | 只属于当事人的一次性疑问 |
| 需求 | 行为或诉求背后的真实目标、阻力或未满足结果 | 表面功能要求 |
| 策略／方法 | 含原理和判断条件、能指导一类决策的方法 | 单句话术、窄技巧、一次性待办 |
| 灵感／种子 | 尚未验证但值得试验的构想 | 无上下文脑洞、他人的想法误记为自己的 |
| 故事／案例 | 有情境、变化和结果，能支撑一个判断 | 流水账、无结论趣闻 |
| 金句 | 脱离上下文仍准确、凝练且有传播力 | 普通陈述的断章取义 |

每类允许为零。用“损失测试”控制数量：半年后丢失这条，是否会影响判断、创作、产品或行动？不会就不收。

默认一小时录音通常只保留 3—10 条；内容密度确实很高可以更多，但必须逐条说明其独立价值。

### 4. 保留证据

每条候选至少包含：

- 一句话提炼；
- 类别；
- 说话人；
- 原话短摘；
- 时间戳或可定位位置；
- 为什么值得保留；
- 置信度与不确定性。

引用只取支撑判断所需的最短片段，不把整段转写复制进结果。

## 默认输出

```markdown
# {录音主题}｜关键点水库

> 来源：{文件或链接}
> 类型：{录音类型}
> 参与人：{已确认人物}
> 证据状态：{时间戳／说话人是否完整}

## 候选清单

### 1. {一句话提炼}
- 类别：观点／需求／策略……
- 说话人：……
- 原话：“……”
- 位置：00:12:34
- 保留理由：……
- 置信度：高／中／低；不确定点：……

## 决策与待办（原稿明确出现时）

- 决策：谁决定了什么
- 待办：谁在什么时间前做什么

## 建议深挖

- #N：为什么值得进一步分析
```

不要为了格式完整强行填满七类；空类别可以不显示。

## 深挖选中项

对用户选中的每一条依次完成：

1. **原话证据**：上下文、说话人、位置，区分原话与转述。
2. **命题提纯**：把候选改写成可判断的清晰命题。
3. **逻辑链**：前提如何导向结论，中间是否跳步。
4. **支撑与反证**：现有证据、缺失证据、最强反例。
5. **适用边界**：对谁、在什么条件下成立。
6. **信度评级**：事实可靠性和推理可靠性分开判断。
7. **下一步用途**：研究、试验、内容、产品或行动；只建议，不擅自写入外部系统。

深挖输出必须区分三层：

```text
录音里明确说了什么
→ 可以合理推断什么
→ 仍需验证什么
```

## 质量门槛

- 没有把摘要数量当成质量。
- 每个洞察都能定位到原稿；缺时间戳时明确说明。
- 观点、需求和策略没有混为一类。
- 他人的观点没有错归给用户。
- 默认阶段没有越权修改其他资产。
- 深挖结论包含反证、边界和信度，不只是扩写原话。
