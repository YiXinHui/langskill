# 推档时扫经历

## 适用条件

一个观点要往上推一档（尤其从「有判断有理由」推到「能反复用」），缺用户的亲历、转折，或别的场合讲得更深的说法。只起了个头、用户没打算推档时不扫。用户当场就能补的，直接问他，比扫更快。

## 输入

- 要推档的观点页，以及它缺哪一块：转折、场景、验证，还是另一次更完整的表达。
- 主题词 3—6 个：标题里的判断、关键说法、用户习惯的同义说法。
- 大概的时间段：用户记得是哪段时间的事就按那段，记不得先扫最近一年。
- 来源清单和取用方式：读 `../personal-config.md`；没有时问用户有哪些记录来源。

## 执行与判断

1. **先查知识库本身**：同一观点的旧页、课程笔记、文章稿。找到同一个观点，按「一个观点一页」合并，不另建。
2. **再按来源扫，按价值排序**：日记、内观类笔记（经历和转折最多）→ 录音转写（同一观点在不同场合讲的深浅）→ 会话日志（观点怎么改的）→ 其他文档。只有动作没有叙述的来源（待办清单）不扫；要临时导出的来源（个人微信）只在用户点名时扫。
3. **缩范围**：先用主题词和时间段。限额接口（比如按天查、单日有条数上限的笔记接口）不要整年硬扫；要扫整年，先告诉用户大约多久。
4. **守边界**：用户标为私密的标签不读；日记里涉及别人的心事、人际矛盾，不作为候选。
5. **列成小水库**：每条一句话提炼、原话短摘、出处链接、能补上哪一块（转折、场景、验证、新的说法），加勾选框。用户勾了才用。
6. **用的时候**：勾选的经历按用户口吻写进观点页，链回原处，不另存一份。同一段经历被两个以上观点用到，再提炼进故事库，观点页链过去。

## 输出与验收

- 小水库的链接，和一句话说明：扫了哪些来源、什么时间段、用了哪些主题词，哪些来源没扫及原因。
- 扫不全（接口限额、来源离线）时如实说扫到了哪里；没找到就说没找到，不编。

## 常见误判

- 把扫到的别人的话、读书摘抄，当成用户自己的经历。
- 把日记里的私事、和同事的矛盾搬进观点页。
- 扫到一半就停，却报「没有相关经历」。
