# 演变、结构与交汇规范

需要研究对象的形成过程、当前关系或未来变量时，完整读取本文件。

## 一、区分两种“往前追”

| 类型 | 回答的问题 | 常见对象 |
|---|---|---|
| 理论根脉 | 构成它的思想、概念与方法从哪里来 | 概念、方法、系统的知识地基 |
| 对象演变 | 这个具体对象经历什么选择和转折才成为今天这样 | 产品、公司、行业、人物、事件、制度、决策 |

两者可以串联，但不能混写。理论可能早已存在，对象却在很晚才吸收；结构相似也不证明对象继承了该理论。

## 二、演变研究

### 目标

解释对象当前关键特征的形成原因，而不是写完整年表。

### 过程

1. 列出今天最需要解释的三至五个特征；
2. 为每个特征寻找形成线索：早期条件、关键人物或机构、技术与制度基础、重要选择；
3. 找出真正改变方向的转折点，并回答当时为什么这样选；
4. 识别路径依赖：哪些早期优势后来成为包袱，哪些限制反而塑造了差异；
5. 在更早节点已经不再改变当前解释时停止上溯。

### 写法

以少量形成线组织，每条包含：

```text
早期条件
→ 关键选择
→ 转折事件
→ 对今天留下的结构性结果
```

事实节点附人物、机构、时间和来源；选择逻辑若是推断，明确标注推断依据。

### 常见失败

- 只写近几年新闻，没有追到形成条件；
- 为满足固定年限强行加入与现状无关的古老历史；
- 只列事件，不解释选择为什么发生；
- 把理论首次提出的历史当成具体产品或公司的发展史。

## 三、结构研究

### 目标

以当前为切面，判断对象与其他力量的关系及其真实位置。

### 选择结构单元

按对象选择真正影响其位置的单元：

| 对象 | 常见结构单元 |
|---|---|
| 概念或技术 | 同代概念、替代方案、上下位理论 |
| 产品 | 用户群、竞品、互补品、渠道与平台 |
| 公司或行业 | 竞争者、上下游、规则制定者、资本与客户 |
| 人物 | 同行、资源、约束、关系网络与角色 |
| 决策 | 选项、收益、代价、不可逆性与机会成本 |
| 事件 | 当事各方、利益、能力、约束和联盟 |
| 情绪或心结 | 内部欲望、恐惧、价值要求和现实约束 |

这些是示例，不是白名单。结构单元由问题决定。

### 每个单元要回答

- 它追求什么，靠什么行动；
- 它为什么会被选择或拒绝；
- 它与研究对象是替代、互补、上下位、依赖还是制约；
- 它的优势在哪些条件下成立；
- 当前有哪些事实证明这种位置。

分析要让读者看见对象“如何活着”，不能只罗列功能参数。当前事实和趋势使用最新可靠来源。

## 四、交汇判断

交汇把时间因果与当前关系放在一起，形成单看任一维度得不到的判断。

根据任务需要回答：

1. 当前核心优势源自哪次早期积累或选择；
2. 当前核心短板是否是旧环境里的合理选择在新环境中变成包袱；
3. 它占据的真实位置是什么，哪些对象最可能替代或增强它；
4. 哪些关键变量一旦改变，现有判断就必须更新；
5. 用户现在应该观察、保留、调整或试验什么。

最后给出一句可证伪的综合判断，并列出失效条件。不要用“未来值得期待”“情况复杂”代替判断。

## 五、研究节奏

- 轻量或定向任务一次完成。
- 完整研究默认连续推进，在结尾集中给用户校准点。
- 只有对象歧义、来源冲突、不可逆决策或用户明确要求时分段暂停。
- 用户中途提出反馈时，只回滚受影响的假设和后续结论，不机械重做全部研究。

## 六、质量自检

- 演变是否解释当前特征，而非仅有年表；
- 理论根脉与对象历史是否清楚分开；
- 结构是否选对关系单元，并有当前证据；
- 是否解释人、组织或产品为何作出那些选择；
- 交汇是否产生新增判断，而非摘要；
- 未来判断是否附关键变量和失效条件；
- 简单问题是否被及时收住。
