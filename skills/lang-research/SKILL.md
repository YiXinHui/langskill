# Lang Research

把一个对象放回它的知识根脉、形成过程和当前关系中，得出能够用于今天的判断。

## 定位

本 Skill 是统一研究编排器。用户只需说明想搞懂什么，不需要在“溯源”和“演变结构”之间选择。

按任务需要组合四个研究维度：

1. **根脉**：它在知识世界里是什么，建立在哪些思想、学科与方法之上；
2. **演变**：它如何沿关键选择、转折和路径依赖成为今天的样子；
3. **结构**：它今天与谁竞争、互补、包含或制约，处在什么生态位；
4. **交汇**：把前三者合起来，判断真实优势、包袱、位置和关键变量。

四个维度是内部工具，不是每次必须展示的固定目录。只做对当前问题有解释力的部分。

## 职责边界

- 一条实践经验或边界清楚的概念：快速辨名、找根、说明差异，不扩成长报告。
- 方法、机制或知识系统：辨析概念并追踪多条理论根脉；需要解释形成与现状时继续研究演变、结构和交汇。
- 产品、公司、行业、人物、事件或决策：以演变和结构为主，理论溯源只追真正解释当前特征的根。
- 只核验原话、人物、日期或资料出处：完成来源核验即可，不启动完整研究。
- 用户要进一步创作、存档、发布或转化为其他产物时，先交付研究地基；再调用当前环境中匹配的下游能力，不在本 Skill 复制实现。

普通事实查询、代码排错、单纯创作或已经明确范围的执行任务不触发本 Skill。

## 自动路由

### 1. 恢复真实问题

先判断用户最终需要什么变化：获得准确名称、建立完整理解、看清当前选择，还是形成下一步行动。

从现实意义进入：谁正在承受什么代价，为什么现在值得研究。上下文足够时直接判断，不让用户填写研究模式。

研究对象复杂或与相邻概念容易混用时，先用最少必要篇幅分开这些概念，再开始追根。只辨析会改变研究边界或结论的词，不堆术语表。

### 2. 识别研究维度

| 用户真正要解决的事 | 默认维度 |
|---|---|
| “正规军里叫什么、理论地基、往根上追” | 根脉 |
| “怎么走到今天、为何变成这样” | 演变；必要时补根脉 |
| “和谁不同、现在什么位置、有哪些选择” | 结构；必要时补演变 |
| “系统研究、完整搞懂、未来怎么变、该怎么判断” | 根脉 + 演变 + 结构 + 交汇 |
| 原话、首创者、日期、出处核验 | 来源核验 |

这些是判断信号，不是硬编码白名单。一个问题同时包含多个目标时，自行串联完整流程。

### 3. 决定深度

- **轻量**：一个名称、一个概念或一个边界；一次回答完成。
- **定向**：两个左右的研究维度；形成一份连贯分析，不机械补齐其他部分。
- **完整**：复杂对象或明确要求系统研究；依次完成根脉、演变、结构和交汇。

不要用字数、固定年代或固定节点数代替深度。继续上溯或扩展对比，直到更早节点或更多对象已经不会改变当前解释；此时停止。

### 4. 说明意图并开始

只用一句话告诉用户本次会重点研究哪些维度以及原因，然后开始工作。

默认连续完成，不在每个阶段机械停下。只有以下情况才暂停：

- 研究对象有两个以上同等合理解释，选择会改变结论；
- 关键来源冲突，无法在不猜测的情况下继续；
- 下一步涉及覆盖正文、对外发布、权限或其他高影响动作；
- 用户明确要求分段校准。

## 四维研究工作流

### A. 根脉：确定知识身份

执行根脉研究时完整读取 [证据与输出规范](references/research-and-output.md)。

先辨析容易混用的概念，再选择单一主链或多根脉森林。对每条关系区分：直接祖先、形式化地基、治理原则、平行类比、后代工具和当代综合。

找不到精确概念时说明最接近的候选与差异；研究者自己的综合不得伪造成历史人物或原始文献的说法。

只做来源核验时，先找到可定位的原始文本、权威版本或正式档案，让它承担核心出处结论；二手研究用于解释编纂、年代和争议，不能单独证明“最早”“首创”或原话。

### B. 演变：解释它如何形成

需要演变、结构或交汇时完整读取 [演变、结构与交汇规范](references/evolution-structure.md)。

围绕当前特征寻找少量关键来源线、转折点和选择逻辑。重点是因果与路径依赖，不是编年史。理论根脉与对象历史分开：前者说明“思想从哪里来”，后者说明“这个具体对象怎么长成”。

### C. 结构：确定当前位置

识别真正决定对象位置的关系单元：竞品、替代方案、上下游、利益相关者、内部力量或决策选项。说明它们的目标、行为、优势、限制和彼此关系，不用参数表代替理解。

涉及当前市场、产品、公司、政策、人物或趋势时，核验最新事实。

### D. 交汇：形成新增判断

交汇不能只是前三部分的摘要。根据任务需要回答：

- 当前优势来自哪条早期积累；
- 当前短板是哪次合理选择留下的包袱；
- 它在现有结构中的真实位置；
- 哪些变量会让判断失效或未来发生改变；
- 这对用户当前系统、决策或行动意味着什么。

推断必须标为推断，并说明从哪些证据推出。

完整研究收尾必须给出一句可证伪的综合判断，并明确列出会使该判断需要修改的关键变量或失效条件；不能只给方向性总结。

## 证据纪律

- 原著、原始论文、标准、官方档案和一手数据优先；二手资料只作导航。
- 作者、年代、术语首创、直接引语、继承关系以及当前状态必须核验。
- 历史继承、理论奠基、结构相似和现代应用分别表述，不把“像”写成“源自”。
- 不因年代古老就把某项思想判定为最重要的根；解释力和证据强度分别判断。
- 来源与结论就近放置；无法核验时降低结论强度。

## 输出方式

### 轻量回答

现实问题 → 正式名称 → 重合与差异 → 一句主脉络 → 一句话判断。

即使用户要求简单，回答也要完整包含三个最小部件：①正式名称与定义；②口语经验与正式概念的关键差异；③它与上位原则或最容易混淆概念的一句关系。三项可以压缩进三句话或一个短段落，但不能省略其中一项；总篇幅仍应服从用户的简洁要求。

### 定向研究

现实入口 → 本次研究维度 → 关键发现 → 关系或因果结构 → 回到用户问题 → 边界。

### 完整研究

```text
现实入口与研究对象
→ 概念辨析与理论根脉
→ 形成过程与关键转折
→ 当前结构与生态位
→ 交汇判断
→ 对用户的意义、行动与失效条件
```

用户中途修正某一部分时，更新受影响的假设和后续判断，不要求重新选择 Skill 或重做无关部分。

默认先在对话中交付。只有用户明确要求保存，且目标位置或当前项目规则已经清楚时才落盘；不要替公开用户假定私人目录。

## 权威优先级

1. 当前任务的明确要求和用户确认过的判断；
2. 当前对象的一手事实、真实运行结果和原始材料；
3. 当前项目最近一级规则与用户提供的权威源；
4. 本 Skill references；
5. 本 `SKILL.md` 的通用规则。

## 禁止事项

- 不让用户先学习 Skill 菜单，再决定研究方法。
- 不因为具备四个维度，就给每个简单问题套完整长报告。
- 不把理论根脉与具体对象的发展史混成一条时间线。
- 不把结构分析写成没有因果和人的参数罗列。
- 不把交汇写成摘要，或把推断冒充事实。
- 不强凑学科、年代、对比对象、中西对称或未来预测。
- 不未经确认覆盖成品、公开发布或执行外部高影响动作。
