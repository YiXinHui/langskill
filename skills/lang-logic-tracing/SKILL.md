# Logic Tracing｜逻辑卡点梳理

把论证拆到相邻两步都能接受审查。不要把“因此”“显然”“本质上”当成推理。

## 职责边界

- 输入可以是一句话、一段文章、一个商业判断或一套方案。
- 输出是经审计的逻辑链、卡点和修补记录。
- 不替用户做全面行业研究；缺少事实时标明待核验，不编造证据。
- 不因为结论听起来合理就放过中间断点。

## 工作流程

### 1. 锁定起点与终点

先用一句话写清：

```text
从「前提」出发，要论证「结论」。
```

区分事实、定义、假设和价值判断。用户把它们混在一起时，先拆开再继续。

### 2. 铺开最短完整链

把推理拆成编号步骤，每步只完成一次推进：

```text
1. [事实/定义/前提] ……
2. [因为第1步，并且满足条件X] 所以 ……
3. [因为第2步] 所以 ……
```

相邻两步发生层级切换时必须加桥，例如：技术能力不能直接跳到组织策略，个体案例不能直接跳到群体规律。

### 3. 对每个连接做五项检测

| 检测 | 要问的问题 | 典型处理 |
|---|---|---|
| 必要性 | A 成立时 B 必然成立，还是只可能成立？ | 补条件或降低强度 |
| 隐含假设 | A 到 B 依赖了哪个没写出的前提？ | 把前提显式加入链中 |
| 替代解释 | 同一个 A 能否导向 B 之外的结果？ | 增加排除条件或承认分支 |
| 因果方向 | 是 A 导致 B，还是 B 导致 A，或共同原因 C 导致两者？ | 重写因果结构 |
| 层级一致 | 是否从技术跳到组织、样本跳到总体、描述跳到规范？ | 增加桥接机制 |

### 4. 标注连接强度

每个关键连接只能使用与证据相符的强度：

- `必然`：A 成立就一定有 B。
- `高概率`：通常有 B，但存在明确例外。
- `条件性`：只有同时满足 C 才有 B。
- `倾向性`：A 只提高 B 的可能性。
- `未知`：现有信息不足以判断。

论据只有倾向性时，结论不能写成“必须”“只能”或“必然”。

### 5. 修补，而不是粉饰

按问题类型选动作：

1. 缺一步：补桥接机制。
2. 前提推不出结论：寻找真正有推力的前提。
3. 结论过强：把结论降到证据可支持的程度。
4. 一条链承担多个结论：拆成主链和分支。
5. 事实不足：列为待核验前提，不虚构案例填空。

### 6. 加入反例与可证伪条件

至少给一个最强反例或边界场景，并回答：

```text
出现什么事实时，这条链必须被修改或推翻？
```

如果找不到任何可证伪条件，通常说明结论写得太空或定义在自我保护。

## 输出格式

```markdown
# 逻辑链：{主题}

从「{起点}」论证「{终点}」

## 前置定义与待核验前提

1. [定义] ……
2. [待核验事实] ……

## 主链

3. [因果起点] ……
   - 依据／例子：……

4. [因为第3步，并且满足条件X] 所以 ……【条件性】
   - 条件X：……
   - 依据／例子：……

## 卡点与修补

| 原连接 | 问题 | 修补 |
|---|---|---|
| 3 → 4 | 隐含假设 | 加入条件X |

## 最强反例与边界

- 反例：……
- 结论适用边界：……

## 可证伪条件

- 如果出现……，结论需要修改为……
```

简单论证可以一次完成。超过十步、事实争议大或用户明确要对抗推演时，先给初始链，等用户挑战后再重构最终版。

## 质量门槛

- 每个“所以”都能指出依赖的前一步和条件。
- 定义、事实、假设和价值判断没有混写。
- 关键连接有强度标签，措辞与强度一致。
- 至少检查一个替代解释和一个最强反例。
- 事实不足被诚实标记，没有用虚构案例补洞。
- 最终结论有适用边界和可证伪条件。
