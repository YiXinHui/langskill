# 验证场景

修改目录、模板或脚本后运行 `python3 evals/test_init.py`。所有生成样本都在系统临时目录，结束后清理，不进入 Skill 发现根。

修改公司版模块时另运行 `python3 evals/test_company.py`，核对公司单体工作区的预检零写入、十个职能目录、个性化名称与远端权威、重复执行和冲突保护。

## 公司版模块回归

- 原始场景：用户要求「做一个公司版模板模块，以我的公司为例」。期望：在文件体系模块中增加独立公司初始化分支，抽取十个职能目录，但通用模板不带取样公司的名称、产品、账号和云端 ID；只制作模板时不写现有公司目录。
- 相邻场景：另一家公司提供自己的名称、一个产品子目录和客户云端 URL。期望：这些信息只进入本次目标工作区；远端标为未核验，本地客户索引不伪装成现行状态表。
- 反例：用户要完整的个人加两家公司五大模块体系，或目标已有综合工作区。期望：前者走既有 `init_sot.py`；后者不在同一目标叠加公司版文件，也不覆盖现有 SOT。

## 并入 lang 的路由回归

- 原始场景：用户要求「这个 skill 本体放到 lang skill 里」，之后经 `/lang` 要求建公司版文件体系。期望：`lang/SKILL.md` 直接读取内部 `source-of-truth/README.md` 并运行模块，不再指向独立 `/source-of-truth` Skill。
- 相邻场景：经 `/lang` 要求初始化个人、主营业务、第二业务和归档的完整工作区。期望：仍从同一内部模块走 `init_sot.py`，不丢失原五大模块能力。
- 反例：经 `/lang` 要复诊已有知识系统或设计新的信息流。期望：路由 `/lang-knowledge-system`，不因为提到目录就运行初始化脚本。

验证的问题：

1. 新目标的预览和缺失检查是否保持零写入？
2. 一键初始化是否产生五大模块、专项规范、权威表、可达的相对链接和 AI 指针？
3. 重复运行是否字节和修改时间不变？已删的模板文件是否可补齐？
4. 自定义名称、空格名称、关闭第二业务、分项配置云端权威时，目录与文档能否正确衔接？
5. 已有 SOT 或用户改过的规范是否保留？出现冲突时，其他缺失项是否也保持不写入？
6. 根目录/子目录/文件软链接、文件占据目录、路径穿越、未知配置字段、重复 JSON 字段是否在写入前拒绝？
7. 修改已保存配置、模板版本不兼容时，是否拒绝自动迁移？
8. 标准模板能否生成主营业务、第二业务、个人品牌、产品线与公众号账号目录，且使用通用名称？调整后能否替换产品线、改名和关闭第二业务？

## 本轮用户反馈回归

- 原始场景：“初始化我的文件体系”，尚无模板选择 → Agent 先展示原体系骨架，问使用模板还是调整；未回答前不执行创建。
- 相邻场景：“按我的情况调整，只有一家企业，做企业培训” → 沿用已知信息，补问缺失名称后生成调整配置，不保留原模板的无关产品和第二业务；不再询问是否允许创建。
- 反例：“就用标准模板，放到这个新目录”或重跑已有系统 → 已有明确配置选择，直接预检/执行，不强制重复问卷。

对话分支按 Skill 与引用文档人工走查；自动测试只校验提示步骤的存在和 CLI 产物，不声称已测自然语言触发率。

## 模板去品牌回归

- 原始问题：用户要求复用“自己的文件系统模板”，Agent 错把原作者公司、品牌和真实产品目录名一起加入。期望：标准模板仅复用目录结构和管理规范，使用通用占位名称。
- 相邻场景：直接选择模板并要求打包给学员。期望：生成目录、选择提示、配置说明、安装包均使用通用名称，不因来源于个人系统而绑定个人实体或账号。
- 反例：使用者在“自行调整”分支明确提供了自己的公司名与产品名。期望：仅本次配置和目标目录使用这些名称，不覆盖可分发的标准模板。

## 独立沙盒发现的遗漏回归（1.1.2）

- 祖先软链接：目标的祖先是用户自建链接时，预览与创建均拒绝、对照目录零写入；相邻场景为深层链接；反例为用户明确传入无链接的真实路径以及受约束的 macOS 系统别名。
- URI 链接：百分号名称的文件夹保持原名，链接编码后按 URI 解码能找到目标；相邻场景为百分号与空格混用；反例为普通名称与远端 HTTPS URL，不改变原远端 URL。
- 别名冲突：品牌/账号只差大小写、补充目录与必需文件仅差扩展名大小写，均创建前拒绝；相邻场景为 Unicode 规范化和父目录别名；反例为普通不同名称正常运行。已有小写 AI 入口保持原样。
- 基础职责：补充配置不能重定义显式目录或隐式父目录；相邻场景为知识单元父目录；反例为在基础目录内增加真正的新子目录。

自动测试按 URI 语义核对链接。路径检查采用保守大小写和 Unicode 判重，不声称覆盖恶意并发换链、硬链接、所有平台保留名或 I/O 原子性。

这些测试验证脚本与生成产物；不证明 Agent 的自然语言触发率，不验证使用者云端链接的可用性，也不代表已迁移原有业务数据。
