# 配置与使用

最低只需 Python 3.9+ 和一个目标文件夹。脚本不读取本机原作者资料，不连接飞书，不在目标根目录外创建业务目录。

首次通过 Skill 初始化时，先按 [模板选择](template-choice.md) 询问。原样使用标准文件夹结构传 `assets/filesystem-template.json`；通用结构传 `assets/config.example.json`；调整版传临时 JSON。直接运行 CLI 不带配置仍采用通用值，这是脚本兼容行为，不替代 Skill 的首次选择步骤。

| 字段 | 含义 | 默认值 |
|---|---|---|
| main_company | 主营业务名称，生成 `03-名称/` | 主营业务 |
| secondary_company | 第二业务名称，生成 `04-名称/`；设为 `null` 可省略 | 第二业务 |
| personal_brand | 内容工作区名称，生成 `03-…/03-内容/名称/` | 个人品牌 |
| public_account | 公众号工作区名称，生成 `03-…/03-内容/名称/`，不得与个人品牌同名 | 公众号 |
| projects_root | 代码工程位置，仅写入说明，不在此处建文件 | `~/Projects` |
| extra_directories | 按模块补充目录及用途；用于产品线、账号和自选子目录 | `{}` |
| authorities | 数据类别到云端权威 URL 的映射；`null` 表示新工作区采用本地 | 见下表 |

名称只允许一个目录层级，不含斜杠、路径穿越、控制字符或文件名保留字符。配置拒绝未知字段，避免拼写错误导致意外落点。缺省字段使用默认值。

路径按大小写折叠与 Unicode 规范化保守判重，即使文件系统区分大小写，也不允许两个目录仅靠这些差异区分。百分号、空格等名称在生成链接时使用 URI 编码。

目标根路径及其祖先不能经过自建软链接，也不能含 `..`。macOS 由 root 拥有、且指向标准 `/private/` 对应位置的 `/var`、`/tmp`、`/etc` 系统别名只在祖先位置允许；其他软链接拒绝。拒绝后应由用户明确提供真实目标路径，不自动换路径继续写入。

`extra_directories` 的分组为 `knowledge`（知识体系）、`personal`（个人资料）、`main`（主营业务）、`secondary`（第二业务）、`archive`（归档）。每组填写相对于该模块的 `"子目录/下级": "用途说明"`；支持多层，不允许绝对路径、隐藏治理目录、路径穿越或覆盖基础职责。公司改名后这些路径仍跟随对应模块，不需要重写根目录名称。关闭第二业务时应一并移除 `secondary` 的补充目录。

基础职责包括基础结构自动形成的父目录，如 `02-客户/`、`03-内容/`；不能通过补充配置给这些目录重新定义用途。创建前会核对全部计划中的文件和目录，含名称别名冲突；这不等于防御恶意并发换链或保证 I/O 故障下的事务回滚。

例如：`{"main": {"01-产品/企业培训": "企业培训产品资料入口"}}`。删去标准模板中的某个补充条目即可不创建该产品/账号目录。基础结构中的核心目录与索引不是任意增删项；复杂层级调整需同步改相关规范与引用。

| authorities 键 | 权威范围 | 未配置云端时本地落点 |
|---|---|---|
| knowledge | 个人成熟知识 | `01-知识体系/`，具体资产按成熟度路由 |
| goals | 年度目标、月度复盘、愿景 | `02-个人资料/年度目标/` |
| company_knowledge | 公司可复用制度、执行、培训知识 | `03-名称/04-运营/` |
| customers | 客户列表、当前状态 | `03-名称/02-客户/客户索引.md` |
| customer_events | 沟通事件流水 | `03-名称/02-客户/沟通记录/` |
| customer_materials | 客户稳定档案和原始材料 | `03-名称/02-客户/档案与材料/` |
| products | 产品定义、方案和定价 | `03-名称/01-产品/` |
| hr | 人员、招聘和候选人资料 | `03-名称/08-人力资源/` |

云端值使用完整 `https://…` URL。填写即声明该类别云端优先；初始化只标注“用户配置，未联机核验”。本地对应目录用于入口、草稿、按需缓存或历史文件，不再独立维护同类正式正文。客户三个类别分别配置；一处来源不能自动代替另一处。

不要把访问密钥、Cookie、登录口令放进配置。标准模板只保留结构和通用占位名称；使用者的真实公司、品牌、产品、账号和私人 URL 只写入其临时配置及目标目录，不写回可分发 Skill。

## 常见调用

在 `lang/source-of-truth/` 模块目录运行（也可给脚本绝对路径）：

```bash
python3 scripts/init_sot.py --root "$HOME/Desktop/个人工作系统" --config assets/filesystem-template.json --dry-run
python3 scripts/init_sot.py --root "$HOME/Desktop/个人工作系统" --config assets/filesystem-template.json
python3 scripts/init_sot.py --root "$HOME/Desktop/个人工作系统" --check
```

定制：按用户选择复制 `assets/filesystem-template.json` 或 `assets/config.example.json` 到临时配置文件，填入自己的名称、补充子目录与 URL，再传入 `--config '/该文件.json'`。脚本保存首次配置与初始化日期；后续重跑自动读取。

通用配置提供基础结构；标准模板额外展示按产品和公众号账号划分的子目录，名称统一用“产品A／产品B”“主号／副号”等通用示例。两者均不带原作者的公司名、品牌名、实际产品名、客户数据、飞书 ID、历史文件数量或特定自动化的长期授权。原体系中已迁至飞书的类别，只有使用者明确配置远端来源时才采用远端权威规则。初始化新系统不意味着修改原作者现有权威关系。

## 来源与维护依据

基于原体系的 Source of Truth、知识体系元系统、原料隔离协议、公司/个人/第二业务/归档治理入口抽取，模板基线日期为 2026-09-21。此 Skill 自带可移植模板，不依赖原作者电脑路径。

发生冲突时采用当前更具体的规则：知识单元采用 `主题.md`，不带领域前缀；归档包含参考资料、过程资料、工具三个分区；不复制历史飞书节点树，不预建未实施的云端节点。主题推演的 15 篇/30 天阈值保留为检查提醒，不触发自动删除。
