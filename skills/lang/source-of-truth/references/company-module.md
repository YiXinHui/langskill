# 公司版模块

## 适用与输入

用户要为一家公司单独搭建文件管理体系时使用，不创建个人知识体系、个人资料、第二业务或全局归档。用户只要「做一个公司版模板」时，交付可复用的模板与执行入口，并用临时目录验证；不向现有公司目录灌入空模板文件。

最低输入是一个**独立公司目标文件夹**。未给目标时先确定落点；不要默认在现有业务目录执行。公司名称可在配置中填写；未提供时通用模板使用 `公司名称`，实际初始化前应替换为使用者确认的名称。具体业务产品、账号、客户、员工、合作伙伴和云端资源均不从取样公司复制。

## 模板结构与调整

[公司结构](../assets/company-structure.json) 按职能组织：`01-产品`、`02-客户`、`03-内容`、`04-运营`、`05-开发`、`06-财务`、`06-行政`、`07-素材`、`08-人力资源`、`09-历史归档`。两个 `06-` 表示两个并列职能；后续使用者可按自己的目录规范调整模板代码和引用，不把编号当成数据权威判断。

目录存在不能证明它是某类数据的正式权威源。模板只为**新工作区**提供职能占位；复制既有公司的现状时，须回读其当前总索引、最近目录规则和实际数据来源。

[公司通用配置](../assets/company-template.json) 包含公司名、代码工程根、补充子目录及八类权威源。补充子目录写成已有职能目录下的相对路径，例如 `"01-产品/企业培训": "企业培训产品入口"`；不得重定义基础目录或 `.docs`。权威源只接受无凭据的完整 HTTPS URL；`null` 表示新工作区默认本地维护。配置中的远端入口只登记，不声称已连接或核验。

## 初始化与验收

1. 首次创建时展示上述十个职能目录，并让使用者选择直接使用通用结构或调整公司名、补充目录、权威源；已明确选择或已初始化时沿用，不重复问。
2. 将调整后的 JSON 放在目标根之外的临时位置，展示目标与配置后运行预检：`python3 scripts/init_company.py --root '/目标/公司工作区' --config '/临时/配置.json' --dry-run`。原样通用模板用 `--config assets/company-template.json`。
3. 无冲突时去掉 `--dry-run` 执行，再用 `python3 scripts/init_company.py --root '/目标/公司工作区' --check` 验收；已有状态会自动复用 `.docs/sot-company-config.json`。
4. 回读 `.docs/SOURCE_OF_TRUTH.md`、职能目录的 `.docs/README.md` 和 `AGENTS.md`，检查命名、路由、权威源与本地角色。脚本返回 0 且无缺失/差异才报告模板初始化通过。

遇到已有内容/类型冲突时整次零写入，不强制覆盖。换新子目录，或按已授权范围人工对账。初始化不迁移、整理或升级旧公司目录；既有公司治理应以现有 SOT 和最近目录规则人工衔接。
