# 初始化时的模板选择

首次初始化且用户尚未选择配置时，先读本文件和 [标准配置](../assets/filesystem-template.json)，展示以下骨架，再询问选择。

```text
01-知识体系/      卡片笔记、知识单元、方法论、金句、故事、工具箱、录音分析、他山之石、原料隔离
02-个人资料/      年度目标、内观记录、个人文档、车辆证件
03-主营业务/      产品、客户、内容、运营、开发治理、行政、素材、人力资源、历史归档
04-第二业务/      财务发票、合同报表、证照、宣传、工资、支付、日常资料、文档资料
05-归档/          会话日志、录音、参考资料、过程资料、工具
```

主营业务中的产品子目录采用 `产品A/`、`产品B/`，内容目录采用 `个人品牌/选题`、`个人品牌/复盘`、`公众号/主号` 和 `公众号/副号`。这些只是通用示例，使用者可以改名或移除示例子目录。

完整的基础子目录由 `assets/structure.json` 定义，补充目录只在配置 JSON 维护，不另复制一棵基础树。

## 先问这一题

“初始化时，你想直接使用上面的文件夹模板，还是按自己的情况调整？”

- **使用模板原样创建**：采用 `assets/filesystem-template.json`，保留通用目录名称，配套管理规范一起生成。
- **按我的情况调整**：在标准模板上改名、替换产品/账号目录或关闭第二业务；不需要示例子目录时，可从 `assets/config.example.json` 的基础配置起步。

这是配置选择，不是再次申请执行权限。使用当前宿主支持的问答方式；用户已经明确选了模板、给了配置，或明确要求直接采用默认值时，不重复问。否则等待回答，不能把未回答当成选择了推荐项。已有工作区重跑直接复用保存配置。

## 选调整后的最少补充信息

用一次简短问题收集尚未确定的项：主营公司名称、是否保留第二业务及其名称、个人品牌与公众号目录名、需要保留/替换的产品线和补充子目录。已有答案直接沿用，不强迫填写每一项；用户说使用通用配置时直接采用通用 JSON。

Agent 在临时配置文件修改上述字段。产品和账号子目录在 `extra_directories.main` 修改；改公众号名称时，同时改其账号子目录前缀。增加目录要有用途；不将客户名单或私人文件带入模板。若要变更基础层级或删掉带有索引/规范引用的核心目录，先说明影响，再按用户要求同步修改执行方案和引用；不要仅声称配置已支持任意删除。

展示最终五大模块名称、关键调整项和目标位置，随后直接预检并创建，不再增加一轮确认。

## 模板复制范围

“使用我的模板”指复用文件系统的结构、分类逻辑和管理规范，不是继承原作者的公司、品牌、产品、账号或业务事实。标准配置和示例文档只能使用通用名称；具体使用者的名称仅在其自行调整后的配置与生成工作区中出现。

模板不附带文件正文、员工/客户名单、账号凭据、飞书资源 ID 或私人自动化授权。默认在新工作区本地维护；用户要求连接自己的飞书时再配置各类别权威源，不能把原体系的云端资源当作其他使用者的资源。
