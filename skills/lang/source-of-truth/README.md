# Source of Truth 文件系统初始化（lang 内部模块）

## 目标与边界

把知识、个人方向、主营业务、第二业务、归档组织成可检索、可维护的文件系统；也可单独初始化一家公司的职能工作区。
创建目录、管理规范、空白业务索引和 AI 入口；不迁移旧资料、不安装同步任务、不创建云端资源。
已有单一业务目录的整理治理交给现有目录治理能力；本模块不代替文件整理或日常知识萃取。

## 输入与输出

- 完整工作区最低输入为目标文件夹；未指定时使用 `~/Desktop/个人工作系统`，执行前告知落点。公司版最低输入为独立的公司目标文件夹；未指定时先问落点，不把模板写进现有业务目录。
- 模板只复用目录结构与管理规范，名称使用通用占位；不继承原作者的公司、品牌、产品、账号或资源标识。
- 内置 [标准文件夹模板](assets/filesystem-template.json) 和 [通用配置](assets/config.example.json)。首次初始化先选择“使用模板”或“自行调整”；已有明确选择或已初始化配置时不重复问。
- 用户只要「公司版」「单个公司模板」时，读取并执行 [公司版模块](references/company-module.md)，使用 [公司通用配置](assets/company-template.json) 和 [公司结构](assets/company-structure.json)；不走五大模块初始化。若只是要求制作模板，完成 Skill 模块及沙盒验收，不在使用者现有公司目录直接运行初始化。
- 用户说“按我的现状复制”时：先读取其现有 SOT 和最近目录规则，只抽取目录、称呼、权威源配置；冲突依据更新且更贴近对象的规则处理。云端节点须用可用连接器核验后才能声称有效。
- 产出以目标根目录下 `.docs/SOURCE_OF_TRUTH.md` 为唯一管理总入口；模块 `.docs/README.md` 负责专项规则。
- 最终给出目标位置、目录清单、规范入口、创建与保留情况、未核验的外部源。

## 完整工作区执行

脚本路径相对本模块目录 `skills/lang/source-of-truth/`。只需 Python 3.9+ 标准库，无网络、账号或其他 Skill 硬依赖。

1. 首次初始化且尚未选择配置时，读取并执行 [模板选择](references/template-choice.md)：展示标准骨架，询问“直接使用标准模板，还是按自己的情况调整？”等待用户回答，不把未回答当作默认选择。已选模板、已给配置或重跑已有工作区时直接沿用。
2. 选择原样使用时传入 `--config 'assets/filesystem-template.json'`；选择调整时读取 [配置说明](references/configuration.md)，在发现根之外的临时 JSON 中调整公司名、第二业务、品牌、公众号与补充子目录。用户明确要通用结构时使用 `assets/config.example.json`。展示最终配置和目标后直接执行，不重复请求许可。
3. 运行只读预检（下面示例采用标准模板；调整版换成实际配置路径）：

   ```bash
   python3 scripts/init_sot.py --root '/目标/个人工作系统' --config assets/filesystem-template.json --dry-run
   ```

   检查目标、目录和冲突；预检本身不写入。
4. 无冲突则使用同一参数去掉 `--dry-run` 执行，不再要求二次许可。已有文件内容或类型冲突时保持零写入；换用新的子目录，或按用户已授权范围先人工对账，不提供强制覆盖选项。
5. 运行 `python3 scripts/init_sot.py --root '/目标/个人工作系统' --check` 验证。已初始化的目录会自动复用 `.docs/sot-config.json`，无需重复传配置。
6. 回读 SOT 与模块入口，核对名称、资料路由、权威源和 AI 入口。脚本返回 0 且无缺失/差异才能报告本次模板初始化验收通过。

## 重复执行与配置变更

- 相同配置可重复执行；完全相同的文件保留，缺失项补齐。
- 已有内容与模板不同会报告冲突并停止，不覆盖用户维护的治理文档。检查中的“差异”不等于用户内容错误。
- 初始化后修改名称或权威源涉及管理规则变更，先读取已有 SOT 和模块入口，再由人工/Agent 同步维护；初始化脚本不承担迁移或模板升级。
- `.docs/sot-config.json` 是初始化参数记录，不是第二份业务权威索引。后续事实以 SOT 和实际权威源为准。

## 完成标准

- 完整工作区的五大模块（关闭第二业务时为四大模块）与所需子目录、规则、索引全部可读。
- SOT 能回答“放哪里、查哪里、哪个版本说了算”；各模块专项规则不与它并列维护同一条正文。
- AGENTS.md、CLAUDE.md 和兼容 SOT 文件都只指向唯一治理入口，不复制规则正文。
- 云端 URL 只登记，不声称创建、同步或验证了云端系统；未配置云端时明确本地为新工作区权威源。
- 验证脚本和代表性场景见 [验证说明](evals/cases.md)，仅维护/修改 Skill 时读取。
- 公司版验收以独立公司目标下的十个职能目录（财务与行政均为 `06-`）、总 SOT、各目录规则和 AI 入口为准；通用模板不包含来源公司的真实产品、客户、员工、账号或云端 ID。
