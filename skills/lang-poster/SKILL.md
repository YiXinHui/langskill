# Poster｜可编辑海报

本 Skill 是海报执行层：把已确认的信息转成单文件 HTML，并导出可发布图片。

## 权威优先级

1. 用户本轮明确提供的内容、尺寸和参考图；
2. 目标项目的事实源与目录规则；
3. `references/personal-config.md` 中的品牌和素材配置；
4. 本 Skill 的视觉与导出规范；
5. 通用设计经验。

首次使用时，如需固定品牌，复制 `references/public-config-example.md` 为 `references/personal-config.md` 并填写。没有个人配置也可以制作无品牌或由用户本轮指定品牌的海报。

## 制作流程

### 1. 建立交付契约

明确：

- 产物类型和像素尺寸；
- 接收者和看完要采取的行动；
- 唯一核心判断；
- 可出现的产品、价格、时间、地点和承诺；
- 不得出现的内部信息、未确认事实和伪造入口；
- 品牌主体、Logo、二维码和图片是否已授权。

能从现有材料确定时直接执行。只有关键事实、尺寸或真实行动入口缺失且会改变成品时才追问。

### 2. 压缩为一个主要视觉动作

社交海报不是详情页。一张海报原则上只承载一个核心判断和一个主要视觉机制。信息过多时拆成系列，不靠缩小字号硬塞。

默认读取 `references/research-grid.md`：以强结论、一个机制图和清晰结果建立研究感。用户提供参考图时，先抽象空间、层级、节奏、颜色角色和图形机制；不要照搬受保护的 Logo、插画或独特素材。

### 3. 生成单文件 HTML

- 所有内容放在 `.poster` 容器内；
- `.poster` 明确宽、高、`position: relative` 和 `overflow: hidden`；
- 海报元素相对 `.poster` 定位，避免截图错位；
- 优先使用系统字体，并提供可读的字体回退；
- 图片使用稳定相对路径或 base64；
- 没有真实二维码时不放假二维码；
- 不把网页导航、按钮和仪表盘卡片直接当成平面设计。

需要导出或排障时完整读取 `references/export-and-assets.md`。

### 4. 预览、导出、检查

必须完成：

1. 生成可编辑 HTML；
2. 用浏览器预览；
3. 用 `scripts/export_poster.sh` 导出 JPG；
4. 检查实际像素尺寸；
5. 视觉查看文字、图片、二维码和裁切。

不能只生成 HTML 后声称海报完成。

### 5. 交付

优先向用户展示 JPG，并提供 HTML 源稿。说明使用的视觉方向、实际尺寸，以及是否仍缺真实二维码或授权素材。缺失时明确标为预览版。

## 信息与视觉检查

- 第一眼能否读到核心判断；
- 是否只有一个主要视觉动作；
- 字号、对比度和留白在手机缩略图下是否可读；
- 产品名、时间、价格、地点是否与事实源一致；
- 是否出现调试标签、内部术语、虚假数据或假二维码；
- 品牌主体、公司背书和行动入口是否正确；
- JPG 是否真实生成且与 HTML 同版。

## 固定边界

- 不把某个客户、产品或人物事实写进通用规范。
- 不把个人路径、账号、二维码或密钥写进 `SKILL.md`。
- 不因一张参考图自动创造永久风格规范。
- 不把视觉相似误当成像素级复刻授权。
- 用户要求制作时必须产出文件并验证，不能停在建议稿。
