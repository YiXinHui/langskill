# 取证：先搜信息源

适用于做月、周、日计划，列今天的清单，以及日、周、月复盘。出草案或写复盘之前先做，不等用户提醒；只靠执行台和用户口述容易漏掉已经排好的事。

## 搜哪里

默认四类来源（飞书业务资料与飞书妙记分别核验），具体入口（清单名、业务总表、固定群等）写在 `personal-config.md` 的「信息源」一节。

| 来源 | 用什么读 | 计划时看 | 复盘时看 |
|---|---|---|---|
| flomo | `../flomo同步`，按日期范围只读 | 上个周期开始到今天写下的打算、决定、「要做」「明天继续」 | 本周期的记录，作为事实和感受的证据 |
| 滴答 | `../lang-dida` | 本周期有日期的未完成任务、循环提醒，加上与目标相关的清单（含没设日期的） | 本周期的完成记录（`review_snapshot.py`） |
| 飞书业务资料 | lark-cli：日历日程、文档搜索、私有配置列出的业务总表 | 本周期的课程期次、项目下一步和截止、会议纪要里的约定 | 同一批来源里本周期实际发生的事 |
| 飞书妙记 | `../lark-meeting` 的妙记搜索：`lark-cli minutes +search --start <开始> --end <结束> --as user --format json` | 日计划先查前一天完整窗口，再查当天截至查询时刻的记录，补齐昨晚会议的约定；周／月查相关周期窗口 | 日复盘查被复盘日整天（含晚上）；周／月按周期窗口查，提取已发生事实与约定，不用日历或已归档纪要代替妙记搜索 |

私有配置里还列了其他固定来源（例如微信群公告），同样只读、按需取。

## 妙记时间窗与会议路由

- **复盘前一天**：按配置时区查询前一天 00:00 至 23:59:59；仅日期参数的 `--end` 包含当天，所以同一天的 `--start YYYY-MM-DD --end YYYY-MM-DD` 就覆盖全天。不能只查工作时段而漏掉晚间会议。
- **计划当天**：先搜前一天全天的妙记（尤其是昨晚尚未整理的内部会），再搜当天 00:00 至查询时刻，找影响今天的承诺和行动。提前排未来日期时只说明当前可查到的记录，不把尚未发生的会议当证据。周／月窗口超过一个月时分段，按妙记 token 去重。
- 使用 `lark-cli minutes +search --start <ISO8601或日期> --end <ISO8601或日期> --as user --format json`，完整按 `has_more`／`page_token` 翻页。默认按时间窗搜索当前身份可读的记录，不自行增加 owner、参与人或关键词限制；有本轮明确范围才加，不能只搜已有纪要或只查日历。需要正文时按 lark-meeting 的妙记读取流程获取相关内容，标题不能当会议结论。
- 按场景交接，携带妙记完整链接、标题、会议时间、已核实正文和待办线索：内部会（合伙人会、例会、内部讨论）调用「会议纪要」；客户会有具体项目归属时交对应项目管理 Skill，客户关系／跟进交「客户管理」，咨询复盘交「lang-consulting-retro」。完整读取对应 Skill，按其范围执行，不把客户会塞进内部会议纪要。模块工作写入仍须通过 [模块交接](module-handoff.md) 的 CEO 入口；取证和路由不自动授权新增客户／项目资产。
- 搜索失败、部分页不可读、正文无权限，分别列为缺口；“未读到”不能写成“没有会议”。完整搜索无结果时才报告该时间窗内未发现可读妙记，不据此断言会议未发生。

## 怎么用

1. 每条候选注明出处（链接，或清单名加日期），和用户这次说的事合并去重。滴答里 ID 已填在执行台「滴答任务ID」的任务是执行台推过去的，按 ID 排除，不当新候选。
2. 用户没提、但来源里有的，在草案里单列「来源里发现，待你确认」，不自动列成目标，也不替用户判断重不重要。
3. 来源只证明「记过、排过」，不证明重要，也不证明做完；任务打勾不等于业务成果。
4. 某个来源读不到（授权失效、电脑离线），如实列为缺口，继续读其他来源；不编内容，不把「没读到」说成「没有」。
5. 只摘与计划、复盘相关的条目，不整段回显；疑似凭据的内容遮蔽。

## 验收

草案或复盘里写明四类来源各查了什么窗口、发现了什么、哪些没读到；妙记单列实际起止时刻、分页覆盖、发现的会议及路由、未读到的内容；用户事后指出漏项时，能说清是哪个来源没查或没读到。
