# 目标拆解

适用于做本月目标、安排这周、今天做什么。输入是执行台的现状、用户本次的说明和 [取证](sources.md) 的结果；产出是本周期的完整计划草案，用户确认后再写入。

## 333

- **月分两层**：九宫格每个维度最多 3 条月目标；其中「青蛙目标」（必须完成、重点盯的）全部维度合计最多 3 条，在月目标标题最前面加「🐸」。非青蛙目标也是月目标，同样写进执行台，不能因为青蛙名额满了就挪去待办工具。
- **周、日**：全部合计每周最多 3 个周目标，每天最多 3 个待办。是否也分两层，用户还没确认，确认前按合计 3 项。
- 3 是上限，选 1–2 项也可以；不能把一堆事打包成「一项」来凑数。
- 已完成、取消的都留在本周期里，照样占名额（维度名额、青蛙名额都算）。名额满了还要加，按下面的「插入判断」处理：必须说清楚挤掉哪一项、为什么，用户同意后才换；青蛙换人可以把原青蛙降成非青蛙，不必删掉。
- 不属于任何月目标的杂事放在用户原来的待办工具里，不在执行台另开一个待办池。

## 从年到日

先后顺序是年→月→周→日：没有本月目标先定月，本周没有周目标先排周，再排当天。

1. **月**：读年度目标（目标、KR、当前行动、说明），结合用户本月最在意的现实问题，先按维度列全本月目标，再从中选最多 3 条青蛙。每项写清：月目标（可观察的结果）、完成标准、维度、关联年度目标、截止日期（落在本月内）、是否青蛙、滴答清单（这个目标下的待办推到哪个滴答清单，不推就选「不推」）。找不到对应的年度目标就标「待确认」，不能硬挂。用户没提到的维度留空，不替用户补目标；但已知的本月大事（课程、交付、出差）要主动核对有没有漏列。
2. **周**：从周一到周日。选能推动月目标的里程碑，每项关联一条真实的月目标，写完成标准；跨月的周可以挂两个月的目标，但整周合计仍最多 3 项。
3. **日**：选今天能做完、能推动本周目标的最小交付，关联一条真实的周目标；约人见面、单场讲课这类一次性的事挂「关联月目标」，不占周名额，但占当天名额。挂在 🐸 上级下面的周目标和待办，标题最前面也加「🐸」。能拆的待办拆成子任务，每层最多 3 个，还要细分就再拆一层（子任务的子任务），子任务只写进滴答，见 [滴答推送](dida-push.md)。用户没说今天有多少时间，就问一句，或者明说容量还没核实；不保证一定能完成。

成果要能验收：「整理资料」要收敛成「完成某份能直接用的清单，包含哪些项、经本人检查」。「努力、提升、坚持」这类词不能直接当完成标准，要先改写成本周期能看到的结果。

## 插入判断

周期中途临时冒出来的任务或想法，不机械地排到下个周期，也不直接塞进本期；先判断，给出建议和理由，由用户拍板。

1. **先分清是什么**：只是想法 → 记到 flomo 或待办工具的「将来也许」，不进计划；一次性小事 → 挂月目标、不占周名额；要持续投入、能交出成果的事 → 继续往下判断。
2. **看四点**：

   | 问题 | 倾向本期做 | 倾向往后放 |
   |---|---|---|
   | 和本期 🐸 的关系 | 是某个 🐸 的前置，不做会挡住它 | 和本期 🐸 无关 |
   | 时间压力 | 有外部截止，或晚做会返工 | 什么时候做结果都一样 |
   | 体量 | 能切出一小块，放得进本期剩下的时间 | 只能整块做，会挤垮本期 |
   | 代价 | 挤掉的那项损失更小 | 要挤掉 🐸 或有截止的事 |

3. **结论五选一**：本期做（说清挤掉谁）、切一小块本期做、并入已有目标（必须真是同一个成果，不能凑数）、放下个周期、不做。建议里写明依据了哪几点；当天名额满时，切出的小块排到本期内名额还有空的日子。
4. 用户拍板后按本文件其他规则写入并校验；结论不写入执行台的（想法、不做），也要说清记到了哪里。

## 写入前校验

把执行台里同一周期的已有记录（历史迁入的除外）和本次新增、修改的合在一起，组成完整清单，通过 stdin 交给 `scripts/validate_plan.py`：

```json
{
  "level": "month",
  "period": "2026-10",
  "items": [
    {"title": "🐸示例成果", "dimension": ["工作事业"], "parent": "rec示例年度", "done_when": "示例标准", "due": "2026-10-31", "status": "未开始"}
  ]
}
```

- `level` 为 `month`、`week` 或 `day`。月的 `period` 写 `YYYY-MM`；周写该周周一的日期；日写当天日期。
- `parent` 填上级记录的 record_id。月目标的上级是年度目标，周目标的上级是月目标，待办的上级是周目标（一次性的事是月目标）。
- 月、周的条目必须有 `done_when`；月的条目必须有 `dimension`（维度名或列表，跨维度的在每个维度都占名额），`due` 必须落在该月内；`title` 以「🐸」开头即青蛙。状态为「已完成」的月、周条目必须有 `actual_result`。
- 脚本只检查格式和数量，不证明上级记录真实存在，也不判断目标值不值得做；这两点要人工核对。示例数据不要写进用户的表。

校验通过后，按字段合同的「定位已有记录」先查后写：已有的更新，没有的新建；写完回读，核对数量、关联和状态。每日待办回读通过后，按 [滴答推送](dida-push.md) 推到滴答并回填「滴答任务ID」；做今天的计划前，先按同一文件的「回读」核对之前推过、执行台还没结的待办，用户在滴答里延期到今天的也占今天的名额。用户在飞书里手工填超过了名额（月：单维度超 3 条或青蛙超 3 条；周、日：超 3 项），就指出来并协助取舍，不删记录，也不能声称表格本身会限制条数。

## 可视化与计划写入

九宫格目前没有现役入口：v1 仪表盘、v1.1 BaseApp 看板都已取消并删除，v2 妙搭应用另有 PRD 推进。目标、状态或评分写入后，只回读执行台；Agent 不生成九宫格、不调用本地渲染脚本。上线后的入口见私有配置与总控。
