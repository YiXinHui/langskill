# 月周行动覆盖检查

每次日计划、日周月复盘及无人值守晨间例行都执行；复盘已存在、今天草稿未确认，也不能跳过。沿用现有例行入口，不新建调度。

## 逐项取证

1. 完整分页读取本月全部月目标、本周周计划、每日行动；读明确跨月承接的下周计划。只跳过已完成／取消目标的执行安排，不复活历史取消项。每个开放目标都对照原完成标准；一个目标包含多个成果时分支核对，不能用日更掩盖书稿停滞。
2. 每个目标、每个开放周计划都找出下一步：已有有效日行动及实际提醒；专项模块原记录与执行回执；本人明确暂停／延期及下次检查日期；或确实缺行动。循环习惯和直接挂月目标的专项行动也算覆盖，不为了填满周链接再造任务。未来周计划只有本人已确认的延期才能暂时解释空缺，到期重新检查。
3. 用 `scripts/plan_coverage.py` 从 stdin 检查结构遗漏。传 `date`（用户本地日期）、`complete:true`（已完整分页）和 `months/weeks/daily`（各为 record_id→字段值）。按字段合同读取周与月关联、月目标「滴答清单」、每日待办日期、状态、来源记录和滴答任务ID。
4. 核验候选与脚本无法判断的语义缺口：长期主任务冒充当天步骤；旧周已完成但子行动未开始且没日期；子成果已完成而月目标仍未开始；日常模块原提醒存在但个人引用漏失；AI交接没有真实接单/产物/验收。模块刷新脚本只更新已有引用，不能证明没有漏项。

## 写入后验收

- 周计划必须关联真实月目标。当天至周日内的开放个人行动，如果上级月目标配置了推送清单，应有真实滴答任务ID。月目标选「不推」的行动仍按原约定处理。
- 验收已推提醒时，用 `dida_sync.py read` 回读清单、日期和时段，将结果按每日待办 record_id 传入 `dida_readback`。提供该映射时，涵盖快照中所有需要推送且已有 ID 的本周未到期个人行动。缺回执、任务找不到或日期/时段不一致都需要处理。只有 ID 时只能说明已绑定。
- `expected_module_actions` 每项含 `record_id/source_url/task_id`，只放已获授权的原行动。个人引用的来源链接和滴答 ID 必须同时与原行动一致。单项不符先沿原记录核对，重复候选先保留现场。工作状态继续从 CEO 原记录单向同步。
- `coverage` 仍可传 record_id→`{evidence:出处或回执,next_check:YYYY-MM-DD}`，仅在已核实且下次检查晚于当天时用于解释暂缓。正式写入后重新取数，以飞书关联与真实滴答回执验收。脚本只读，候选用于排查。

## 修复与交回

- 已证实的进展、真实上级关联和漏失的已授权逐项引用，核对后补写并回读；引用沿用源日期、状态、原滴答ID，不另建提醒。历史缺少发表证据时只记提醒勾选，不计已发表篇数。
- 未确认的下一步先给建议，具体日期、加量与取舍仍由本人决定；已确认暂停的工作不启动。多项缺口合并问一次，不让本人逐目标重新讲事实。
- 工作执行交对应CEO沿原任务闭环，个人记录来源、真实阶段和下一检查点。待接单不能记成执行中；已派发不能记成完成。专项进度交对应模块核验。
- 月目标终态必须回到原验收标准，子计划完成不能代替整体验收；证据矛盾保留冲突及出处，不能自动结项或追加验收门槛。
- 原记录的实际结果／备注保留当前检查结论、行动或延期链接及下次检查点；更新同一检查条目，不每日重复追加相同缺口。运行态仅存元数据和回执，不另建业务正文台账。
- 晨间私聊沿现有一条消息，只报新增、改变或到期的真实缺口及需要本人决定的事项。无变化不重复催问，不另发机器人通知。发现遗漏不阻塞其他已获准行动或会议交接。

完成时说明已检查的目标/周计划数量、修复项、未安排原因和待决定项；来源分页不完整或专项读取失败就列具体覆盖缺口，不能宣称全查完。
