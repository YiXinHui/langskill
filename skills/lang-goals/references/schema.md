# 执行台字段合同

执行台是一个飞书 Base，六张表按下面的顺序排列。每次开工都要用 `+field-list` 核对现网字段：缺字段、改了名或类型不同，就停止受影响的写入，并报告差异；不要自己补字段或改名。

## 维度

默认用人生九宫格的八个维度：身体健康、财务理财、家庭生活、工作事业、学习成长、人际社交、体验突破、休闲娱乐，中间格是「个人成长」或当年的核心词。用户换了叫法时，以年度目标表里的维度为准，所有表统一用同一套名字。

## 状态

- 月目标、周计划、每日待办：未开始／进行中／已完成／未完成／取消。「未完成」只在周期结束后使用。
- 年度目标：进行中／维持／合并／已完成／取消。

## 六张表

| 表 | 字段（主字段在前） | 说明 |
|---|---|---|
| 年度目标 | 年度维度、年份、年度目标、关键成果KR、当前行动、说明、状态、月目标（关联）、本月月目标（公式）、今年已完成（公式） | 一年一个维度一行 |
| 月目标 | 月成果、月份（公式）、截止日期、维度、关联年度目标、完成标准、状态、实际结果、备注、周计划（关联）、月复盘（关联）、是否本月（公式） | 一个成果一行；青蛙目标在月成果最前面加「🐸」，不另设字段 |
| 周计划 | 周结果、周一、月份（公式）、周（公式）、关联月目标、完成标准、状态、实际结果、每日待办（关联）、是否本周（公式） | 一个结果一行；「周一」填该周的周一 |
| 每日待办 | 待办、日期、关联周结果、状态、滴答任务ID | 一个待办一行；滴答任务ID 只有真正关联了才填 |
| 日周复盘 | 标题（公式）、周期（日／周）、日期、做成了什么、偏差与原因、下次调整 | 每天、每周各一行；周复盘的日期填周一 |
| 月复盘 | 月份（公式）、月初、八个维度的分数、九宫格总分（公式）、月目标（关联）、复盘文档（text，style.type=url） | 一个月一行，月初填当月1号；复盘文档指向该月标题，五问和截图只在文档维护 |

关联字段都是双向的：月目标↔年度目标，月目标↔周计划，月目标↔月复盘，周计划↔每日待办。写关联要用真实的 record_id，不能用标题或链接代替。

## 公式（不手填）

- 年度目标.本月月目标：`[月目标].FILTER(CurrentValue.[关联年度目标].CONTAIN([年度维度])&&CurrentValue.[是否本月]="是"&&LEFT(CurrentValue.[月份],4)=TEXT([年份],"0")).MAP(CurrentValue.[月成果]&"（"&CurrentValue.[状态]&"）").ARRAYJOIN(CHAR(10))`。只汇总本行关联、月份年份等于本行「年份」的本月目标，每条一行，格式为「月成果（状态）」；没有匹配目标时留空。
- 年度目标.今年已完成：`[月目标].COUNTIF(CurrentValue.[关联年度目标].CONTAIN([年度维度])&&LEFT(CurrentValue.[月份],4)=TEXT([年份],"0")&&CurrentValue.[状态]="已完成")`。只计本行关联、月份年份等于本行「年份」且状态为已完成的月目标，空集合为 0；不能使用今天的年份替代本行年份。
- 上述两式的「月目标」与表名同名，使用「关联年度目标包含本行年度维度」限定反向关联，并按本行年份隔离跨年数据。同一年内年度维度名称必须唯一，跨年可同名；核对结果时必须按本行「月目标」中的真实 record_id 逐条计算，不能只看全表总数。若同一年出现重名，先停止受影响的使用并报告。跨年反例：把下一年已完成月目标关联到本年年度记录，本年完成数必须不变，验完删除测试记录。
- 月目标.是否本月：`IF(TEXT([截止日期],"YYYY-MM")=TEXT(TODAY(),"YYYY-MM"),"是","否")`
- 周计划.是否本周：`IF(TEXT([周一],"YYYY-MM-DD")=TEXT(TODAY()-WEEKDAY(TODAY(),2)+1,"YYYY-MM-DD"),"是","否")`
- 月目标.月份：`IF(ISBLANK([截止日期]),"",TEXT([截止日期],"YYYY-MM"))`
- 周计划.月份：`IF(ISBLANK([周一]),"",TEXT([周一],"YYYY-MM"))`
- 周计划.周：`IF(ISBLANK([周一]),"",TEXT([周一],"MM/DD")&"–"&TEXT([周一]+6,"MM/DD"))`
- 月复盘.月份：`IF(ISBLANK([月初]),"",TEXT([月初],"YYYY-MM"))`
- 日周复盘.标题：`IF(ISBLANK([日期]),"",IF([周期]="周","周复盘 ","日复盘 ")&TEXT([日期],"MM/DD"))`
- 月复盘.九宫格总分：八项都空时留白，否则用八项之和除以 8。分母固定为 8，不按已填项数平均；只填了一部分时，汇报里要说明总分还不完整。0 分是有效分。

## 视图

- 月目标：「按月」（按月份分组，最新的在上面）、「看板」（按状态分栏）。
- 周计划：「按周」、「待推进」（未开始和进行中）。
- 每日待办：「全部」、「今天」、「日历」。
- 日周复盘：「日」「周」；月复盘：「全部」（按月初排序）；年度目标：「全部」（按年份分组）。

读数据一律用 `+record-list`，完整确认分页，不靠视图判断有没有记录。日期范围可用ExactDate上下界；月份公式也可按YYYY-MM精确筛选。

## 文档与可视化

- 一年一份月复盘文档，每月一个标题；标题block_id必须从fetch取得，链接用文档URL加#block_id，禁止猜测。每月打分链接指向月复盘记录；原五问正文和历史截图保留。
- v1.1 BaseApp「个人目标看板」路线已按 PRD D11 取消，应用已删除；九宫格可视化改用妙搭（v2，待定）。工作区及执行台归属保留，v1 成果和四个公式字段保留。
- 「是否本月」「是否本周」两个公式字段已存在，并在月目标、周计划的全部现有视图中隐藏；公式按今天日期计算并供看板筛选，不手填；字段存在不表示看板已上线。

## 定位已有记录

- 月目标：同一个月份内比对月成果的标题；周计划：同一个周一内比对；每日待办：同一个日期内比对；日周复盘：周期加日期；月复盘：月份。
- 找到一条就更新它；找到多条就停下，把候选列给用户，不自动合并或删除。

## 历史记录

从旧系统迁入的记录，在备注里写明「…迁入」，并保留原来的状态。这些记录不参与 333 计数，不重新判定完成，也不改。

## 改结构

只有用户明确要求时才做：先导出受影响表的全量记录作备份 → 新建字段并回填 → 逐条对比备份 → 再删旧字段。改完同步更新本文件和总控文档的变更记录。主字段可以直接改成公式类型；关联字段不能改类型。
