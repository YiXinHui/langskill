# 日清单

适用于「今天做什么」「明天做什么」「中午调整」：把本周计划变成一天做得完的清单，中午再调一次。周、月计划见 [目标拆解](planning.md)；当天收口交给 [复盘方法](review.md) 的「每日收口」。

方法来源：邹小强《如何合理安排每日计划，做好一天时间管理》（只管去做成长会直播，2026-02-05）。标「原文」的是课里讲的，其余是本 Skill 为接上执行台和滴答补的执行规则。

## 接口

本模块只产出日计划草案和调整建议：当天的 🐸 怎么选由本模块定，名额上限仍按 333；不改上级记录；滴答里的改动只在用户回「行」后，按 [滴答推送](dida-push.md) 执行。

| 方向 | 内容 | 权威 |
|---|---|---|
| 输入 | 本周周计划（含 🐸）、本月月目标（一次性的事挂这里） | 执行台，字段见 [字段合同](schema.md) |
| 输入 | 今天已定的日程、滴答到期和延期的任务、flomo 里的「明天继续」 | [取证](sources.md) |
| 输入 | 之前推过、执行台还没结的待办 | [滴答推送](dida-push.md)「回读与同步」 |
| 规则 | 🐸 名额上限、条数提醒 | [目标拆解](planning.md)「333」 |
| 输出 | 用户确认后的日计划，按日格式交给 `validate_plan.py` | [目标拆解](planning.md)「写入前校验」 |
| 输出 | 写入执行台、推到滴答 | SKILL.md 流程 6、7，[滴答推送](dida-push.md) |

## 合理的一天：四把尺子（原文）

出草案和中午调整时用来自查。效率再高，离想要的生活越来越远，也不算合理。

- **外，顺应身体和环境**：生病、透支时合理的安排是休息。减量顺序见早上第 4 步，停 🐸 只能用户说。
- **内，尊重自己的节奏**：创造性的事放精力高峰；不比用户平时的节奏排得更紧。
- **远，连接长期愿景**：今天至少有一件推动年度目标。
- **近，滋养当下身心**：用户提到想做的滋养类小事，不当杂事砍掉。

## 早上：排今天

1. **先同步，再给过期的找去向**：按「回读与同步」同步之前推过、还没结的待办；用户在滴答里延期到今天的计入今天。过了日期还没勾的，按 [滴答推送](dida-push.md)「过期没勾」逐条给推荐去向，挪到今天的计入今天名额，和草案一起交给用户。滴答里用户自建的任务按 [目标拆解](planning.md)「插入判断」逐条给去向建议，滴答里的改动由用户做。本周还没有周计划，先回目标拆解排周。
2. **盘可支配时间**（原文：可支配时间＝可工作时长减去已经约定出去的时间）：从日程和来源里列出今天已定的事（会议、课、约人、办事），用用户说的可用时段减去它们，得到几段空隙。用户没说就问一句今天几点到几点能用，不默认按 8 小时算；只给了总时长，就只比总量，不编空隙起止。
3. **选今天的 🐸**（原文「三只青蛙」，按三条原则各选一只，当天合计最多 3 只）：
   1. 推动年度目标的：挂在 🐸 目标下的待办，标题自动带 🐸，有每日节奏的（如日更）每天自动进；本周没有 🐸 周计划，就取最能推动年度目标的那条，`frog_pick` 填「年度目标」。
   2. 重要关系交代的：对用户重要的人（家人、合作方、老板）托付了、用户答应过的事，`frog_pick` 填「重要关系」。
   3. 手头其余事里相对最重要的，`frog_pick` 填「手头最重要」。

   第 2、3 只不挂在 🐸 目标下，也照样标 🐸、在滴答设高优先级。挂在 🐸 目标下的待办已占满 3 只时，第 2、3 只就选不进来：说清缺了哪一类，由用户决定是把某条 🐸 目标下的待办挪到别的日子，还是今天不选第 2、3 只。🐸 必须写进执行台才能计名额；找不到所属月目标的事，问用户挂哪条，或不把它选成 🐸。
4. **装进空隙**：每条估时，合计不超过可支配时间。超了就倒推取舍（原文）：每条判断亲自做、交给别人、降低标准、挪到哪天、不做。顺序守「减量先减非 🐸」：先动不带 🐸 的；🐸 只建议缩小或挪日子，每日节奏的不停。轮到 🐸 时，列两三个选项（缩小到哪一步、挪到哪天）让用户选。装不下的事不留到晚上再说。
5. **把想法变成行动，按类型只补缺的那块**（原文：零碎时间里知道要做什么，就不会去刷手机）：每条待办要坐下就能开始。自查一句：用户打开滴答那一刻，知不知道先点哪、做到什么算完？知道就只写标题；哪块不知道，只补那块，不给每条都写满（狼哥 10-09 定）：

   | 类型 | 例子 | 写多少 |
   |---|---|---|
   | 一看就会 | 日更、站桩、发一条消息、约人 | 只写标题，可加时段 |
   | 要交东西 | 写大纲、做方案、跟课实操一个模块 | 标题写明交付物；描述写第一步（打开哪个链接、看哪一节） |
   | 拍板、审定（AI 做完等用户定） | 需求稿、终稿 | 描述写三行：做完是什么样、第一步、定了在哪说（哪个会话，或直接改文档）；每个要拍板的事写成一条检查项，带推荐答案，同意就勾 |
   | 说不出第一步 | 研究一下、想想 | 还是想法，回「插入判断」，不进今天 |

   标题是动作加对象，不写一串名词。大块的事切成三五分钟、十来分钟就能推进的一步（原文）；子任务按做的先后排，每条一个动作，层级限制见 [滴答推送](dida-push.md)。产出类待办完成以交付物为准。
6. **挂上级**：每条挂一条真实的周计划；一次性的事（约人见面、单场讲课）挂月目标，占当天名额、不占周名额。
7. **出草案**：🐸 在前，注明各属哪条原则；其余按空隙排，可标建议时段（🐸 放精力高峰或最大的空隙）。写明可支配时间怎么算、估时合计，以及「来源里发现，待你确认」的条目。用户说定了才进入校验和写入。

## 中午：调一次（原文）

用户说「中午调整」「下午排不下了」，或上午偏差明显时使用。同样做完 8 件，晚上才发现剩下 4 件会挫败；中午主动挪走，晚上清单清零才有成就感。

1. 按「回读与同步」读上午的状态。
2. 重算下午的可支配时间，和剩下待办的估时对比。
3. 装不下的，建议挪到哪天（看那天的名额）并说理由；顺序同早上第 4 步；剩下全是 🐸 时，列两三个选项让用户选，不替用户定。上午做得快，可以从本周计划里补一条。
4. 用户回「行」后，按 [滴答推送](dida-push.md) 用 `push`（`fields` 只含 `date`）两边一起改日期；用户自己在滴答里改的，下一次同步写回执行台。

## 验收

- 草案写明可支配时间的算法：扣了哪些日程、可用时长从哪来；估时合计不超过它，没核实的明说。
- 每只 🐸 说清属于哪条原则；不挂在 🐸 目标下的 🐸 填了 `frog_pick`，validate_plan 的日计划检查通过。
- 每条待办是行动：坐下就知道先点哪、做到什么算完，挂了真实上级；描述按类型只补缺的那块。
- 过了日期没勾的都给了去向；中午调整和过期去向都只在用户回「行」后才改。

## 常见误判

- 把列出来的事全做完当目标 → 只要求 🐸 做完，其余顺势推进（原文）。
- 按整天的工作时长排事 → 先扣掉已经约定出去的时间。
- 计划定了就不能改 → 中午调一次本身就是方法的一部分。
- 待办写成「想想 X」「研究 Y」 → 那是想法，不是行动。
- 每条待办都写满三行描述 → 一看就会的只写标题；拍板类最容易卡，要写清定了在哪说、带推荐答案。
- 过了日期没勾，自动顺延或自动记「未完成」 → 给去向，等用户回「行」。
- 三只 🐸 全是挂在 🐸 目标下的事 → 重要关系交代的事被挤掉了；说清缺了哪一类，让用户取舍。
