# 复盘方法

先读执行台里本周期的计划、实际结果和上一次复盘的「下次调整」，再按 [取证](sources.md) 搜本周期的 flomo、滴答和飞书记录。计划不等于完成，没填不等于失败；缺事实就标「待补充」。

## 每日收口（3 分钟）

三问：今天做成了什么？哪里偏了、为什么？下次只调整什么？

1. 先按 [滴答推送](dida-push.md) 的「回读与同步」把已推待办的滴答状态同步到执行台（不再逐条问用户），顺带更新上级，并列出滴答里用户自己加的任务、给出建议。用户已经在滴答、flomo 或飞书里操作或记录过的事，不让他重述。
2. 在日周复盘里，周期为「日」、日期为当天的那一行写三问；已有这一行就补充，不另建。
3. 当天没勾的不由 Agent 擅自顺延；过了日期还没勾的，按 [滴答推送](dida-push.md)「过期没勾」给去向，用户回「行」后两边一起改。明天的计划另做，并重新校验 🐸 名额。用户自己在滴答里延期的，按同步结果改日期，并计入新日期的名额。

## 每周复盘（15 分钟）

检查本周的周计划对月目标的推动：做成了什么、偏差及原因、下周最重要的一个调整。

1. 逐项更新周计划的状态和实际结果；标「已完成」必须写出真实结果。
2. 在日周复盘里，周期为「周」、日期为本周一的那一行写三问。
3. 周复盘不打九宫格分，也不要求每天的收口都填满。

## 月末大复盘

1. 读当月计划、日周复盘、唯一月复盘记录及复盘文档对应月份。用复盘文档字段定位；只读fetch取得的标题和正文block_id。已有内容保留，只补充。
2. 月末五问写进年度月复盘文档对应月份：完成情况→兴奋或沮丧→经验教训→打分链接→新发现。用lark-doc局部更新指定正文块，不覆盖整节grid，不改历史截图或其他月份。事实、本人判断与AI建议分开；AI整理内容标「待本人确认」。不把五问写回执行台重复维护。
3. 逐项更新当月月目标的状态和实际结果，写清差距和原因；任务打勾、习惯打卡、截图上的勾都不等于业务成果。
4. 八个维度的分数只来自本人；没给就留空，0 是有效分。只改本人明确给出的格子，写完回读分数和九宫格总分。
5. 最后收束成三句：保留什么、停止什么、下月改变什么。用户确认下月目标后（333：最多 3 只🐸，总条数不限），再按目标拆解写入下月计划；改年度目标需要用户单独明确授权。
6. 文档五问与执行台分数各自回读核对。任何一处失败都汇报部分完成和真实阻塞。

## 验收

日、周复盘短且有动作；月末五问在文档有证据，分数在Base计算，两个写入点均回读。没有把缺失、推断或建议写成本人的事实；正文没有第二份维护源。
