# 模块交接

个人目标管理统筹整个人的目标、跨领域优先级、可支配时间和状态；专项模块负责本领域的计划、执行和复盘。具体模块入口、权威记录及推送清单读本机配置。

## 做计划或复盘时

1. 先读模块本周期已有记录；没有记录或需要新计划时，读对应 Skill 并按其已实现的工作流执行。模块未实现或读取失败就说明缺口，不能用一句“交给模块”代替执行。
2. 汇总各模块的成果、下一步、时间需求和待本人判断的问题。个人层保留上位目标、逐项引用与来源链接；模块已有的业务待办不再独立维护第二份。各模块当日重点合并核对可支配时间及 333，不能因拆成多个模块增加名额；历史引用行保留，不作为第二份执行待办重复计数。
3. 从已确认的周期节奏补齐当天行动，尤其是每日节奏的 🐸。清单满、工作忙或换了维护模块，都不是自行停掉的依据；用户明确停了才停。
4. **已确认的当天行动必须核验执行提醒**：查其权威待办和滴答任务；核对标题、实际清单、当天日期、状态及任务 ID。先查已有 ID 和当天同任务，找到就复用；没有才由负责模块写权威待办并推送、回填 ID，个人层回读结果。一个任务只由一处维护。
5. 清单先按模块归属选择。一个月目标混合多个领域时，不能让整条月目标的默认清单覆盖具体行动的模块归属。个人层直接管理的行动沿用滴答推送流程；专项训练细节仍留给教练，只推一条执行提醒。
6. 用户本次明确要求推送，优先于旧配置中的“不推”；同步改正对应配置和总控口径，再写入并回读。月目标、训练处方和长期统计不因此自动变成滴答任务。

## 个人日计划：一件事一条引用

用户已确认的行动逐条显示在个人「每日待办」，不能把几件事塞进一条总览，也不能只写在昨天复盘或回复里。工作项由模块维护，个人行是同步的引用。

- 新增引用先查模块原记录及已有个人行，按「来源记录」中的 Base、表、记录 ID 定位，不按会变化的标题或日期重复新建；同一来源找到多行就停止并报告。每行只放一个行动，「待办」只取原事项首行，详细步骤、交付物、验收与执行反馈留在原记录。
- 「来源记录」填可点击的模块原记录完整链接；「日期」「状态」「滴答任务ID」由原记录单向同步。沿用同一滴答 ID，不在个人侧再次推送；没有真实个人上级时不硬挂周／月目标。纯个人行动仍按原流程关联上级并管理滴答。
- 排计划、中午调整、复盘前，以及模块完成本轮更新后，运行 `python3 scripts/module_sync.py --config references/personal-module-sync.json --apply`，再读当天入口。它遍历全部引用（含已完成），只更新个人显示字段，不写模块或滴答，不建、删记录。当前是调用时刷新，不是后台实时监听；读取失败如实报状态未刷新，不冒充已同步。
- 本机 JSON 配置只保存目标表、已核实的模块坐标、字段映射和状态映射，不含凭据。顶层为 `target: {base_token, table_id}` 与 `modules: [{host, base_token, table_id, fields: {title, date, status, task_id}, status_map}]`。各值从现网读取；公开安装没有该私有文件时，先按当前用户已接入模块配置，不借用别人的资源。
- 源状态映射必须明确：待办对应未开始，已完成对应已完成，取消对应取消；原表有个人表不支持的状态时由配置确定映射，未映射就停止写入，不推断完成。缺原记录、缺字段、来源未配置或提醒 ID 意外丢失时保留原引用并报告，不清空绑定、不补建任务。`--apply` 省略时只读并报告差异。
- 校验全局日计划时，每个实际行动只放一次；引用和原模块行动不是两个名额。模块行动的 `parent_type` 用 `模块待办`，`parent` 用已回读的原记录 ID，另填 `module` 和 `source_url`。合并本人各模块及纯个人行动后核对时间和 333。
- 验收个人「今天」实际筛选：行动逐行可见、来源可打开、标题及日期／状态／ID与原记录一致；重复刷新不新增、不重复推送。时间预算和取舍放当天计划说明或复盘，不伪装成一条可勾选的总览任务。修改工作安排或完成工作时，交给负责模块处理原记录，再刷新个人引用。

## 收口

逐项接回：权威记录链接、负责模块、是否本期已完成、滴答清单和任务 ID、回读结果。已完成的当天任务保留完成事实，不再新建一条未完成提醒；产出类仍要核对交付物。任一项未推成功、没回填或无法核验，就报告部分完成，不能只写“今晚留时间”后宣布计划完成。
