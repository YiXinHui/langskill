# 模块交接

个人目标管理统筹整个人的目标、跨领域优先级、可支配时间和状态；专项模块负责本领域的计划、执行和复盘。具体模块入口、权威记录及推送清单读本机配置。

## 做计划或复盘时

1. 先读模块本周期已有记录；没有记录或需要新计划时，读对应 Skill 并按其已实现的工作流执行。模块未实现或读取失败就说明缺口，不能用一句“交给模块”代替执行。
2. 汇总各模块的成果、下一步、时间需求和待本人判断的问题。个人层保留上位目标、当天总览与来源链接；模块已有的业务待办不再复制为个人执行待办。各模块当日重点合并核对可支配时间及 333，不能因拆成多个模块增加名额；历史引用行保留，不作为第二份执行待办重复计数。
3. 从已确认的周期节奏补齐当天行动，尤其是每日节奏的 🐸。清单满、工作忙或换了维护模块，都不是自行停掉的依据；用户明确停了才停。
4. **已确认的当天行动必须核验执行提醒**：查其权威待办和滴答任务；核对标题、实际清单、当天日期、状态及任务 ID。先查已有 ID 和当天同任务，找到就复用；没有才由负责模块写权威待办并推送、回填 ID，个人层回读结果。一个任务只由一处维护。
5. 清单先按模块归属选择。一个月目标混合多个领域时，不能让整条月目标的默认清单覆盖具体行动的模块归属。个人层直接管理的行动沿用滴答推送流程；专项训练细节仍留给教练，只推一条执行提醒。
6. 用户本次明确要求推送，优先于旧配置中的“不推”；同步改正对应配置和总控口径，再写入并回读。月目标、训练处方和长期统计不因此自动变成滴答任务。

## 个人当天总览

模块接回且用户已确认日计划后，必须在个人「每日待办」的当天入口留下总览；只写在昨天复盘的「下次调整」、模块会话或回复里不算完成。

- 复用现有字段，不改 Base 结构。先按「日期」查全当天记录，以日期加「待办」前缀 `日计划总览｜` 定位；没有才建，一条就更新，多条先报告。未确认草案不建，已有用户内容只补本次缺口。
- 「待办」首行写 `日计划总览｜MM/DD：当天重点`，正文只放已确认的重点摘要、模块权威记录的完整链接、个人安排、可用时段、估时和取舍。模块的详细步骤、执行状态、成果和提醒仍只维护原记录；总览是当天安排的索引，变更时从原记录重新汇总。
- 总览不是执行任务：「状态」「滴答任务ID」「关联周计划」「关联月目标」留空，标题不以 🐸 开头，不推滴答、不增加 🐸 名额、不参加行动条数或完成率。新增后检查默认「未开始」是否被自动填入；若有，按该记录 ID 清空并回读。正常个人执行待办仍照原流程挂上级、推送及同步。
- 校验全局日计划时不把总览行放入 `items`；模块行动各放一次，`parent_type` 用 `模块待办`，`parent` 用已回读的模块权威记录 ID，另填 `module` 和 `source_url`，不用无关个人周／月目标凑关联。同一实际任务按权威记录或滴答 ID 去重后再合并核对 333，原模块的目标链仍在原处维护。
- 写完按当天视图的实际日期筛选再读：确认总览可被「今天」查到、源链接正确、没有新建重复提醒。当天没有新增个人行动，也不能因工作全部交给模块而漏掉已确认计划的总览。

## 收口

逐项接回：权威记录链接、负责模块、是否本期已完成、滴答清单和任务 ID、回读结果。已完成的当天任务保留完成事实，不再新建一条未完成提醒；产出类仍要核对交付物。任一项未推成功、没回填或无法核验，就报告部分完成，不能只写“今晚留时间”后宣布计划完成。
