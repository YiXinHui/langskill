# 个人目标管理

## 目标与边界

把年度方向拆成月成果、周结果和每日待办，再用复盘闭环。一个项目文件夹承载总控、执行台和年度月复盘文档：目标、日周复盘、月末八维分数写执行台；月末五问写年度月复盘文档对应月份。本地不建正文副本。九宫格可视化目前没有现役入口：v1 文本仪表盘、v1.1 BaseApp 看板都已取消并删除，v2 改做独立的妙搭应用，另有 PRD 推进；上线前本 Skill 不创建、不刷新任何可视化。

不做：季度复盘；替用户选目标、判定完成或打分；任务自动同步（待办工具只读取证）。

## 输入与输出

- 输入：周期，加上用户这次说的重点或结果；复盘还需要真实发生的事。先读执行台和已有记录，只问会改变结果的缺口，不让用户重述已有内容。
- 输出：已写入并回读核对的记录或文档，以及简短汇报：完整链接、改了什么、阻塞与未验证项。
- 探索性讨论只给草案；用户说「定了」「写进去」「安排上」才写入。

## 流程与按需读取

1. **每次先定位项目**：读 `references/personal-config.md`（本机私有，不进仓库），拿到总控文档和执行台地址；文件不存在时，读取并执行 [初始化](references/setup.md)，先找已有项目，找不到再建。接着读总控文档的「入口」「执行台里怎么看」「节奏与规则」「还没做」；旧月末条目与现网字段有冲突时，以字段合同及入口分工为准，再按 [字段合同](references/schema.md) 核对执行台现网字段；对不上就停止写入并报告差异。
2. **先取证**：做计划、列清单、做复盘之前，都先读取并执行 [取证](references/sources.md)，搜 flomo、滴答和飞书里本周期的相关记录，产出带出处的候选和缺口。
3. **做本月目标、安排这周、今天做什么** → 读取并执行 [目标拆解](references/planning.md)，产出本周期的完整草案。
4. **今天收口、周复盘、月末复盘** → 读取并执行 [复盘方法](references/review.md)，产出复盘记录和计划状态的更新。
5. **写入计划前**：把本周期已有记录和草案合成完整清单，用 stdin 交给 `python3 scripts/validate_plan.py`（输入格式见目标拆解）；失败就改草案，不绕过。
6. **写入**：lark-base、lark-doc 全程用户身份，先父后子，每次写完立刻回读。月末五问与分数分处写入，两边均回读。部分失败如实说，不能说整体完成。

## 完成标准

- 草案和复盘前已按取证搜过三个来源，写明各查了什么、哪些没读到。
- 每条计划都说得清：做成什么、怎样算完成、挂在哪个上级、何时截止。
- 符合 333（月：每维度最多 3 条、🐸青蛙合计最多 3 条；周、日：合计最多 3 项），已完成和取消的也算；validate_plan 通过。
- 复盘只写用户说的和有证据的事；分数只来自本人，没给就留空。
- 写入已回读，汇报给了链接；没建成或没验证的入口如实报告。

## 红线

- 不改权限、owner、分享范围；不删记录、字段、视图，除非用户这次明确要求。
- 不覆盖用户已填内容，只改这次涉及的格子。
- 历史迁入的记录（备注里写着「迁入」）不套 333，也不改。
- 日常任务不改 Base 结构；要改结构时，按字段合同末尾的「改结构」执行，并同步更新总控文档。
