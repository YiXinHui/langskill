# 初诊对话与追问选择

## 1. 不用固定问卷

每轮只选择一个最可能改变候选方向的问题。选择顺序通常是：

1. 当前说法能否落到一件近期真实事件；
2. 事件链缺了哪个关键节点；
3. 哪个角色或原始记录可以校验；
4. 哪个缺口会决定应该做 AI、自动化、数据治理还是组织动作；
5. 什么证据会推翻当前候选。

已经回答的问题不重复问。用户一次提供大量信息时，先整理并指出最关键的一个缺口。

## 2. 常见入口与首问

| 用户入口 | 优先首问 |
|---|---|
| 关键员工离职／经验流失 | 哪个人明天不来，哪件真实业务会先停？最近一次是什么？ |
| 想做 AI 中台／驾驶舱 | 哪个管理决定现在最慢或最容易错？最近一次决定依据了什么？ |
| 想做 CRM／销售智能体 | 选一条最近成交或流失的客户，从第一次接触讲到结果。 |
| 员工人效低 | 最近哪项工作花时最多、返工最多或等待最长？谁能提供一条样本？ |
| 数据很多但不会用 | 最近一次本该由数据支持、最后却靠经验拍板的决定是什么？ |
| 不知道从哪里 AI 化 | 如果只能改善一个经营结果，老板最不能接受哪种损失继续发生？ |

这些问题是示例，不是固定题库。用户已经提供答案时直接进入缺口，不机械重问。

## 3. 真实事件七个槽位

| 槽位 | 要弄清什么 |
|---|---|
| 触发 | 什么信号让工作开始，谁发起 |
| 输入 | 从哪里拿到哪些信息，哪个来源可信 |
| 动作 | 谁依次做了什么，使用什么工具 |
| 判断 | 根据什么决定下一步，哪些依赖经验 |
| 输出 | 结果交给谁，什么状态算完成 |
| 异常 | 缺字段、冲突、失败或插单时如何处理 |
| 反馈 | 何时知道结果好坏，错误如何被发现和修正 |

## 4. 证据状态

面向用户只使用自然语言状态：

- **已提供样本支持**：用户提供了可查看的真实记录、文件、截图、操作或结果；
- **用户陈述**：某个角色这样描述，但尚未用原始记录核验；
- **当前推测**：根据已有信息形成、仍可能被推翻的解释；
- **尚需确认**：缺少会改变结论的信息。

用户对近期事件的口述仍属于“用户陈述”，不能因为描述具体就升级为客观记录。

## 5. 高信息增益动作

优先推荐一个可执行动作：

- 找一条正常样本和一条失败样本对照；
- 让另一个角色复述同一事件；
- 现场走一遍真实操作；
- 查看字段、日志、报表或历史结果；
- 让第二责任人尝试接手；
- 用历史数据回放或影子运行候选方案。

不要把“再多访谈一些人”当成默认答案；说清要找谁、看什么、它会改变哪个判断。
