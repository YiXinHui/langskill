# 假设驱动的企业 AI 初诊对话

## 方法定位

企业咨询不是把客户业务流程问成一张完整表，而是不断完成四个动作：

```text
听懂业务和目标
→ 形成可被推翻的工作假设
→ 选择最能区分假设的样本或问题
→ 根据证据收敛、转向或停止
```

麦肯锡公开材料把问题解决描述为结构化模糊挑战、识别关键问题、建立事实基础并用假设持续验证。本初诊保留这条骨架，但问题选择主要来自真实企业售前咨询中反复有效的做法：理解客户靠什么赚钱和被选择，判断价值链位置与增长上限，再用现场样本暴露隐性知识、异常规则和采用条件。

- [McKinsey：Problem-solving interview](https://www.mckinsey.com/careers/interviewing)

## 一、问题质量门槛

发出问题前，在内部回答五件事：

1. 这个回答可能确认、否定或区分哪个工作假设？
2. 它会改变候选优先级、证据动作或下一问吗？
3. 这是用户的真实经验，还是业内人人都知道的常识？
4. 用户能否从刚发生的工作中直接回答，而不需要替顾问完成整份分析？
5. 有没有比继续问更高信息密度的动作，例如看样本、做对照或现场演示？

如果前两项都答不出来，不问。

如果答案只是“订单下单后打单、仓库发货、客户签收”“客户可能先咨询也可能直接购买”这类常识，不问。只有当完成定义、责任边界或异常处理本身可能改变判断时，才继续深入。

### 一回合推进一个判断

“一个问题”不是“收一个字段”。一个合格回合通常包含：

1. 一句复述当前业务事实；
2. 一句暂定判断或分岔；
3. 一个能够改判的问题或验证动作。

例如：

> 听下来，你们不缺可销售的产品，可能真正受限的是普通代理人无法稳定完成方案判断。我先核一下：询价量翻倍时，最先顶不住的是找方案、算价格，还是向客户解释为什么这样选？

这比连续问“谁接手订单”“何时算完成”更像咨询，因为答案会决定应该检查知识、计算、销售表达还是组织容量。

## 二、冷启动方式

没有具体主题时，默认问：

> 我先不急着问你们流程。用一句话说说：你们主要靠什么产品或服务赚钱，客户通常是谁？如果这次已经有最想改变的结果，也一起说上；没有也没关系。

用户只回答一部分时，先基于已有内容形成最小理解，不机械把另一部分补成表格。

用户说“不知道怎么回答”时，降到：

> 没关系，你只说“我们主要卖什么”就行，产品名或服务名都可以。

不要再换成职责菜单、症状菜单或完整案例作业。企业老板通常更容易从产品和生意开口；后续再根据叙述判断是否需要确认回答者角色。

用户一开始已经给出问题、目标或事件时，跳过冷启动，直接做“复述 + 假设 + 区分问题”。

## 三、咨询推进的六个阶段

六个阶段是思考顺序，不是必须逐项展示的问卷。用户一次说清多项时直接跨越；证据推翻假设时可以退回上一阶段。

### 阶段 1：听出业务逻辑和当前议程

需要知道的不是工商简介，而是：

- 公司靠什么产品、服务或关系创造收入；
- 谁付钱，谁使用，谁影响成交；
- 客户为什么选择它而不是替代方案；
- 这次最想改变什么业务结果或战略动作。

优先跟随用户的自然叙述。必要时才补一个关键缺口。

高价值问题方向：

- “客户最后为什么选你们，而不是同行或自己解决？”
- “你们今年最想推动的变化是什么？”
- “这项生意真正赚钱的是哪一类产品或客户？”
- “这个结果现在靠什么维持：位置、关系、流量、产品、专家，还是流程？”

不要把“典型客户是谁”独立成必答字段。只有客户类型会改变价值逻辑时才问。

### 阶段 2：做一次战略切分

业务背景足够后，不立刻盘正常流程。先选择一个最能揭示关键约束的切面。

常见切面：

| 切面 | 想区分什么 | 例子 |
|---|---|---|
| 客户选择 | 真正竞争力与可复制能力 | 客户找你是价格、关系、产品、速度还是判断能力？ |
| 价值链位置 | 谁得到价值、谁愿意付费 | 上游更需要你，还是下游更需要你？ |
| 增长上限 | 业务为什么无法线性扩张 | 量翻倍后先缺人、缺流量、缺判断还是缺交付能力？ |
| 专家依赖 | 哪种经验难以复制 | 普通员工与资深员工处理同一输入，结果差在哪？ |
| 行为摩擦 | 为什么现有系统没被使用 | 员工明明有系统，为什么仍转发给另一个人处理？ |
| 更新与反馈 | 自动化能否长期维持 | 规则多久变一次，错了多久能被发现？ |

一次只选一个切面。把当前判断说出来，让用户能够纠正。

### 阶段 3：形成候选假设

在后台维护 1—3 个候选解释，而不是边听边锁定一个产品。

假设写法：

```text
因为［观察到的业务事实］，
当前可能受限于［约束／单点能力］，
如果成立，会影响［经营结果］；
但只要看到［反例／改判信号］，就应撤回或调整。
```

示例（非固定答案）：

```text
因为服务量增长主要靠增加资深内勤，
当前可能受限于方案判断无法复制，
如果成立，会限制响应速度和服务半径；
但如果普通员工借助现有资料已经能稳定拿到同等结果，就不应把专家知识当首要约束。
```

不要把“想做销售智能体”“想做驾驶舱”直接当成假设结论。产品名只是客户提出的一个解法。

### 阶段 4：选择能检验假设的真实样本

只有现在才进入具体业务。样本必须服务于某个假设。

优先级：

1. 现场拿一条真实输入，让当前人员实际处理；
2. 对比表现好与表现差的两条样本；
3. 让资深与普通员工处理同一输入；
4. 查看真实输入、输出、字段、聊天、表格或结果；
5. 口述最近一次事件。

### 样本走查槽位

不要求一轮填完。只检查与假设有关的部分：

| 槽位 | 观察重点 |
|---|---|
| 触发与输入 | 信息是否齐全，什么缺失会让后续全部白做 |
| 业务判断 | 哪些规则写得出，哪些仍靠资深人员识别 |
| 动作与工具 | 员工实际怎么做，为什么绕开标准系统 |
| 输出 | 用户真正先需要什么，哪些内容过早出现反而增加摩擦 |
| 异常 | 边界案例、冲突、拒绝条件、临时规则怎么处理 |
| 反馈 | 多久知道错了，谁负责改规则或知识 |

不要把七个槽位变成七轮固定问答。现场演示已经暴露的信息直接记入状态。

### 阶段 5：从失败反推改造对象

样本失败后按下面顺序判断：

1. **输入缺失**：关键字段没收集，继续处理只会返工；
2. **规则缺失**：资料有内容，但没有说明怎样使用；
3. **隐性经验**：专家能判断，普通人和 AI 都说不清；
4. **数据结构问题**：图片、聊天或文件无法稳定计算与更新；
5. **交互问题**：必须在某节点让用户确认、选择或留痕；
6. **组织问题**：责任人、激励、权限或采用意愿不足；
7. **风险边界**：错误成本太高，必须保留人工最终判断。

不要把每次失败都解释为“模型不够聪明”或“提示词还要调”。

### 阶段 6：收敛首期起点

用以下问题比较候选：

- 业务影响是否真实、可观察；
- 当前人工是否已经能稳定拿到合格结果；
- 输入输出和关键规则是否可说清；
- 是否有负责人和真实数据；
- 错误能否人工复核；
- 反馈周期是否足够短；
- 首期能否在一个小范围独立跑通；
- 团队会不会实际采用。

首期通常先服务最懂业务的核心人员，用真实反馈把规则跑稳；再给普通员工或渠道试用；最后才考虑规模化产品。这个顺序是候选判断，不是固定结论，必须结合场景验证。

## 四、两类常见咨询模式

以下来自真实咨询模式的匿名抽象，不是客户案例，不是固定剧本。

### 模式 A：专家服务难复制

典型信号：产品多、规则经常变、普通人员反复请教资深人员、现有系统虽有却没人愿意用。

有效推进：

1. 问客户为什么选这家公司，识别关系、价格与专业判断的权重；
2. 问价值链上谁最需要这项服务；
3. 看活跃客户／渠道规模和当前服务容量；
4. 拿一条真实输入现场跑；
5. 用边界案例测试，观察 AI 与普通人员在哪里误判；
6. 反推输入硬门槛、专家规则和更新机制；
7. 先给核心人员提效，再验证能否下放。

无效推进：从客户咨询一路问到发货、签收和售后，把所有普通流程都问一遍。

### 模式 B：多业务并行、希望全面 AI 化

典型信号：老板同时谈增长、内容、销售、门店、数据和组织，希望建立 AI 能力但不知道节奏。

有效推进：

1. 先听公司战略动作和业务重心；
2. 区分哪个场景最接近业务结果、最容易获得真实反馈；
3. 只在选中的场景里了解当前优秀员工怎样拿到好结果；
4. 找到现有产量、质量、转化或耗时基线；
5. 明确老板是否亲自带头、员工如何采用；
6. 先跑一个点，再扩到营销／产品，再讨论全公司系统。

无效推进：从所有部门列 AI 机会清单，或者一开始讨论完整 AI 中台。

## 五、用户不耐烦或质疑问题时

用户说“这不是常识吗”“这个问题太蠢”“聊不下去”时，不解释原问题的重要性，也不继续下一道问卷。

立即完成：

1. 承认该问题没有提供足够信息增益；
2. 用现有信息说出当前能形成的业务判断；
3. 转到一个战略切面或真实样本；
4. 如果仍缺信息，允许先输出部分判断和缺口。

推荐回应结构：

> 这个问题确实只是在补普通流程，对诊断没有帮助。按你已经说的，我现在更应该判断的是［工作假设］。我换一个能真正区分方向的问题：［高信息增益问题／样本动作］。

## 六、证据与措辞

对外状态：

- **样本支持**：实际看过记录、文件、演示或结果；
- **用户陈述**：某个角色这样描述；
- **当前假设**：根据已有信息形成、仍可能被推翻；
- **判断库支持**：已确认判断提供了比较标准，不代表客户事实成立；
- **尚需确认**：缺少会改变结论的信息。

用户口述得再具体也仍是用户陈述。只有实际查看过样本，才能写“样本支持”，且只支持该样本范围。

首次采用判断库记录时，不要把判断直接改写成“你们的瓶颈就是……”。应说成：

> 基于已确认判断，当前先把［约束］作为工作假设；如果［改判信号］出现，就不应继续沿用这个判断。

若判断库不可用或没有有效记录，而对客户的生意和目标也一无所知，回到冷启动问题。不要为了显得在诊断而索要一条没有明确检验目标的泛样本。

## 七、停止追问条件

出现任一情况，先停止继续采集：

- 连续两轮只获得常识性流程字段；
- 用户已经明确否定当前方向；
- 下一问无法说明会改变哪个判断；
- 当前证据只够做部分初筛，用户要求先看结论；
- 继续需要查看系统、敏感数据或跨角色取证，而尚未获得授权。

停止后输出当前假设、反证、一个最小验证动作和仍缺证据，不用完整报告排版掩盖信息不足。
