# 初诊对话与追问选择

## 1. 咨询式提问漏斗

AI 在后台负责拆问题，用户在前台只需要回答当前最小的一步。不要把“请先讲一个完整真实案例”当成天然容易的问题。

| 阶段 | 目标 | 用户此时只需要做什么 |
|---|---|---|
| 第 0 轮：分流 | 从业务链中选一个起点 | 从具体业务现象中选一项，或回答“说不清” |
| 第 1 轮：定位 | 找到一个容易回忆的小事实 | 回答来源、环节、角色、工具或等待对象中的一个 |
| 第 2 轮：事件 | 锁定最近一次真实业务 | 说出一笔客户、订单、任务、审批或判断 |
| 后续：走查 | 还原事件链并核验证据 | 每轮只补一个会改变判断的缺口 |

第 0 轮的选项应按业务环节或用户能观察到的现象拆分，而不是按 CRM、知识库、智能体等产品拆分。选项是导航，不是结论；不要因为用户选择“客户跟进”就默认答案是销售智能体。

用户已经给出明确问题、业务环节或近期事件时，跳过第 0 轮，直接进入最小缺口。

## 2. 不用固定问卷

每轮只选择一个最可能改变候选方向的问题。选择顺序通常是：

1. 当前问题属于哪条业务链；
2. 能否先落到一个容易回忆的小事实；
3. 当前说法能否落到一件近期真实事件；
4. 事件链缺了哪个关键节点；
5. 哪个角色或原始记录可以校验；
6. 哪个缺口会决定应该做 AI、自动化、数据治理还是组织动作；
7. 什么证据会推翻当前候选。

已经回答的问题不重复问。用户一次提供大量信息时，先整理并指出最关键的一个缺口。

## 3. 常见入口与首问

| 用户入口 | 优先首问 |
|---|---|
| 关键员工离职／经验流失 | 哪个人明天不来，哪件真实业务会先停？最近一次是什么？ |
| 想做 AI 中台／驾驶舱 | 哪个管理决定现在最慢或最容易错？最近一次决定依据了什么？ |
| 想做 CRM／销售智能体 | 选一条最近成交或流失的客户，从第一次接触讲到结果。 |
| 员工人效低 | 最近哪项工作花时最多、返工最多或等待最长？谁能提供一条样本？ |
| 数据很多但不会用 | 最近一次本该由数据支持、最后却靠经验拍板的决定是什么？ |
| 不知道从哪里 AI 化 | 先使用第 0 轮业务现象选择题，不要求用户自己定义经营问题。 |

这些问题是示例，不是固定题库。表中的开放问题只用于用户已经表达对应方向且有能力继续回忆时；用户没有方向或说“不知道怎么回答”时，必须先降级为选择题。

### 按分流结果追一个小事实

| 分流方向 | 第 1 轮示例 |
|---|---|
| 客户与销售 | 最近一条漏跟或反复跟进的客户，是从微信、短视频、转介绍还是其他渠道来的？只回来源即可。 |
| 订单与交付 | 最近一次催进度或返工，发生在开始、执行、验收还是售后？ |
| 日常运营 | 最近一次重复找资料或录入，是从哪个工具搬到哪个工具？ |
| 财务／人事／审批 | 最近一次卡住，是在等人、等数据还是等确认？ |
| 经营数据与判断 | 最近一次等着做决定的数据，属于销售、交付、现金流还是人员？ |

这些小问题只帮助用户找到记忆锚点。得到答案后，再逐步进入真实事件七个槽位，不要在同一轮把来源、人物、过程、影响和数字全部问完。

## 4. 用户说“不知道”时

- 先承认回答门槛过高：“没关系，先不用讲案例。”
- 不解释为什么原问题重要，不要求用户努力回忆，也不要重复原问题。
- 把开放题改成过去一周可识别的日常话语或现象，最多六项，允许只回数字。
- 始终保留“都不像／说不清”，不要逼用户在错误选项里做选择。
- 连续两轮仍无法选择时，问其最熟悉的职责或部门，再从该范围给两三个现象；不要继续扩展问卷。
- 用户表现出不耐烦或要求先出结果时，按现有信息输出部分初筛，不以继续答题为条件。

## 5. 真实事件七个槽位

| 槽位 | 要弄清什么 |
|---|---|
| 触发 | 什么信号让工作开始，谁发起 |
| 输入 | 从哪里拿到哪些信息，哪个来源可信 |
| 动作 | 谁依次做了什么，使用什么工具 |
| 判断 | 根据什么决定下一步，哪些依赖经验 |
| 输出 | 结果交给谁，什么状态算完成 |
| 异常 | 缺字段、冲突、失败或插单时如何处理 |
| 反馈 | 何时知道结果好坏，错误如何被发现和修正 |

## 6. 证据状态

面向用户只使用自然语言状态：

- **已提供样本支持**：用户提供了可查看的真实记录、文件、截图、操作或结果；
- **用户陈述**：某个角色这样描述，但尚未用原始记录核验；
- **当前推测**：根据已有信息形成、仍可能被推翻的解释；
- **尚需确认**：缺少会改变结论的信息。

用户对近期事件的口述仍属于“用户陈述”，不能因为描述具体就升级为客观记录。

## 7. 高信息增益动作

优先推荐一个可执行动作：

- 找一条正常样本和一条失败样本对照；
- 让另一个角色复述同一事件；
- 现场走一遍真实操作；
- 查看字段、日志、报表或历史结果；
- 让第二责任人尝试接手；
- 用历史数据回放或影子运行候选方案。

不要把“再多访谈一些人”当成默认答案；说清要找谁、看什么、它会改变哪个判断。
