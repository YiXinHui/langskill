# 公共诊断方法注册表

## 目的

方法注册表说明当前决策可以调用什么方法、它需要哪些前提、会更新哪个案例对象，以及什么情况下应停止。它防止主 Skill 堆叠框架，也防止把知识结构直接翻译成用户问卷。

注册表只包含公开可分发的方法说明。私有判断通过 `JudgmentProviderV1` 注入，正文不进入公开仓。

## MethodRegistrationV2

```yaml
method_schema: enterprise_ai_diagnosis_method_v2
method_id: public.business-map.v1
name: 最小生意图
status: active
source_class: original_public
source_ref: repository-reference
license_note: MIT-compatible
decision_question: null
updates_case_objects: []
applies_when: []
must_not_apply_when: []
required_inputs: []
procedure: []
outputs: []
limitations: []
misuse_signals: []
change_signals: []
version: v1
```

`status`：

```text
active | experimental | deprecated
```

`source_class`：

```text
original_public | generic_public | licensed_public | private_provider
```

一个方法进入 active 前必须具备：

- 明确的决策问题；
- 更新的案例对象；
- 适用与禁止条件；
- 必需输入和允许的证据强度；
- 可辨认产物；
- 常见误用和停止信号；
- 来源、许可和版本；
- 原始失败、相邻泛化和合法例外评测。

有品牌或第三方归属的方法必须核验原始公开来源、许可和准确表述。不确定时保持 experimental 或不注册。

## 当前 active 方法

### `public.entry-orientation.v1`｜入口方向与产品契约

- **决策问题**：用户准备从整体扫描、具体业务问题还是已有 AI 想法进入？
- **更新对象**：`entry_context`、`interaction.entry`、入口 unresolved decision。
- **适用**：只激活 Skill、只说想做企业 AI 初诊，或当前请求仍无法判断从哪里进入。
- **输入**：当前用户原话与是否为空激活的系统事实。
- **过程**：先用业务语言说明用户能带走初诊判断和下一步验证，再提出一个允许自由回答的入口选择问题。
- **输出**：明确入口，或在用户已经带来实质上下文时直接标记 bypassed。
- **禁止**：用户已经给出具体问题、AI 想法、完整事件、恢复信息或结果请求时。
- **误用**：空激活直接采集公司和职责；展示后台工作流；把三种入口做成必填问卷；后续重复产品介绍。
- **来源**：本仓原创公共方法，MIT。

### `public.business-map.v1`｜最小生意图

- **决策问题**：当前需要哪些生意与回答者坐标，才能正确解释用户的问题？
- **更新对象**：`respondent`、`business_map`、`diagnostic_boundary`。
- **适用**：模糊入口、岗位宽泛、业务信息杂乱，或缺失坐标会改变问题含义。
- **输入**：用户自然介绍与有效 claims。
- **过程**：抽取已知角色、职责、产品、客户、客户结果、收入逻辑和当前范围，只补一个会改变解释的缺口。
- **输出**：足够解释本次议题的最小生意图。
- **禁止**：局部问题边界已清楚且缺失坐标不会改判时。
- **误用**：按字段逐项询问；把行业或岗位标签当完整生意图。
- **来源**：本仓原创公共组合，MIT。

### `public.agenda-map.v1`｜议题组合

- **决策问题**：用户希望发生哪些可观察变化，它们怎样作用于当前职责和业务范围？
- **更新对象**：`agenda.desired_outcomes[]`、`diagnostic_boundary`。
- **适用**：宽泛目标、多个并行目标、手段代替目标或目标作用范围不清。
- **输入**：用户原话、实际职责、生意图。
- **过程**：保留原话，分清收入、利润、成本、时间、质量、风险、判断或新机会等方向及优先关系。
- **输出**：一个允许并行的议题组合。
- **禁止**：目标已经具体到可观察变化且范围明确时。
- **误用**：把“降本增效”自动变成省时间；强制虚假单选；制造心理动机。
- **来源**：本仓原创公共方法，MIT。

### `public.opportunity-portfolio.v1`｜候选工作系统组合

- **决策问题**：当前范围内哪些工作系统值得分开比较？
- **更新对象**：`opportunity_portfolio[]`。
- **适用**：回答者职责较宽、公司级扫描、存在多个目标或多个问题。
- **输入**：生意图、议题组合、实际职责和有来源的现象。
- **过程**：从已知价值链和职责生成候选，记录经营贡献、已知信号、证据和当前优先状态。
- **输出**：足以支持焦点选择的候选组合。
- **禁止**：用户明确只判断一个边界清楚的局部工作时。
- **误用**：依据行业常识补完整流程；为凑数量制造问题；第一处痛点自动 selected。
- **来源**：本仓原创公共方法，MIT。

### `public.focus-selection.v1`｜焦点选择

- **决策问题**：哪一个工作系统更值得在本轮继续诊断？
- **更新对象**：`selected_focus`、候选 `current_priority`。
- **适用**：已有可比较候选，或用户明确限定一个候选。
- **输入**：候选与目标的关系、影响、频率、证据、可验证性、责任与风险。
- **过程**：做定性比较，记录选择依据和改选信号。
- **输出**：provisional 或 confirmed focus。
- **禁止**：候选均为行业推测或尚不知道用户想改变什么。
- **误用**：因为容易做 AI 就优先；用伪精确评分代替证据。
- **来源**：本仓原创公共方法，MIT。

### `public.work-system-map.v1`｜当前工作系统还原

- **决策问题**：选定工作怎样产生结果，损耗可能位于哪项关系？
- **更新对象**：`current_work_system`、`value_map`。
- **适用**：selected focus 已形成。
- **输入**：工作对象和用途、通常模式、角色、动作、输出和自然反馈。
- **过程**：按需还原目的、触发、输入、动作／判断、输出、反馈、交接、异常和责任。
- **输出**：足以区分当前处理方向的工作系统视图。
- **禁止**：焦点未选且用户仍在公司级扫描时。
- **误用**：要求一次讲完整流程；把理想 SOP 当实际运行；从一个动作外推全系统。
- **来源**：通用工作系统分析的本仓独立表达，MIT。

### `public.event-evidence.v2`｜代表性事件取证

- **决策问题**：一个已知模式在具体工作中怎样表现，它能区分什么判断？
- **更新对象**：`current_work_system` 相关 claims。
- **适用**：焦点已选；用户主动给出事件把手，或确认可以轻松回忆代表事件；事件会继续改判。
- **输入**：一件已经发生、可以定位的事件。
- **过程**：识别触发、输入、动作、判断、交接、输出、反馈与差异。
- **输出**：事件范围内的证据和一个仍未决的分岔。
- **禁止**：只有“经常出错”等模式、焦点尚未选、事件答案不会改变动作或用户需要搜索记忆时。
- **误用**：把模式改写成“最近一次”；重复询问用户已经给出的错误与发现方式；扩大事件中的信息关系或发现时间；用“是否适合 AI／AI 关键取决于”包装尚未完成的工作系统追问；单例升级为公司事实。
- **来源**：通用事件走查实践的本仓独立表达，MIT。

### `public.value-loss-map.v1`｜价值损耗定位

- **决策问题**：当前工作关系损害了什么结果、成本、周期、质量风险或组织资产？
- **更新对象**：`value_map.loss_points[]`、`value_map.relevant_dimensions[]`。
- **适用**：工作系统已有足够结构，用户提出损失或机会。
- **输入**：有来源的工作现象和当前目标。
- **过程**：只启用相关价值维度，把损耗连接到具体工作关系。
- **输出**：可核验的损耗方向和替代解释。
- **禁止**：当前只有抽象目标，没有工作系统或现象。
- **误用**：逐项盘问五本账；把释放时间直接写成已创造价值；用共现写因果。
- **来源**：本仓原创公共组合，MIT。

### `public.intervention-fit.v1`｜AI 介入适配

- **决策问题**：AI 能否改变当前工作系统中的一个动作、判断、接口或反馈关系？
- **更新对象**：`intervention_assessment`。
- **适用**：焦点、输入、当前动作、自然反馈和责任已经足以判断。
- **输入**：方法成熟度、输入、反馈、风险、责任与采用权相关 claims。
- **过程**：区分自动化、增强、混合和非 AI；比较基础条件与最小验证。
- **输出**：四类 canonical AI status、介入机制、候选改变和改判信号。
- **禁止**：角色、输入、反馈或责任只能靠行业常识补齐时。
- **误用**：从产品名称直接生成方案；虚构 ROI、周期或稳定性；把共创探索承诺为生产系统。
- **来源**：本仓原创公共方法，MIT。

### `public.source-contrast.v1`｜来源与反例比较

- **决策问题**：不同来源支持、削弱或纠正了哪个案例对象和判断？
- **更新对象**：claims、corrections、候选与假设。
- **适用**：不同角色说法冲突、AI 查看材料或用户纠正。
- **输入**：带来源、范围和核验状态的 claims。
- **过程**：同层比较，保留分歧，不按职位或时间自动裁决。
- **输出**：更新后的证据状态和结论范围。
- **限制**：材料更多不代表更有代表性；共现不建立因果。
- **来源**：通用证据审计实践的本仓独立表达，MIT。

### `public.next-decision.v1`｜下一决定与动态收敛

- **决策问题**：现在应提问、阶段总结、出结果、暂停还是修复？
- **更新对象**：`unresolved_decisions[]`、`interaction.next_move`。
- **适用**：每次状态更新后。
- **输入**：案例 readiness、未决问题、前提、答案分支、用户负担、能量和公开边界。
- **过程**：只有可回答且会改变决定的问题才能进入 ask；其他情况选择 checkpoint、result、pause 或 repair。
- **输出**：一个明确 next move。
- **限制**：analytics 不驱动终止。
- **误用**：固定回合、固定题数、固定时间；`insufficient_evidence` 自动停止；非终局回复没有问题也没有交付。
- **来源**：本仓原创公共方法，MIT。

### `public.repair-and-resume.v2`｜纠偏与恢复

- **决策问题**：用户纠正、疲劳或暂停后，怎样保持案例与关系连续？
- **更新对象**：corrections、ruled_out、interaction、last_checkpoint 与相关案例对象。
- **适用**：wording／fact／frame／goal／boundary correction、fatigue、pause、resume。
- **输入**：有效 claims、纠正、当前焦点与恢复胶囊。
- **过程**：撤回旧表达并更新对象；暂停保存最小胶囊，恢复只使用有效内容。
- **输出**：修复后的案例或可恢复 checkpoint。
- **限制**：不分析用户人格，不为旧问题辩护。
- **来源**：本仓原创公共方法，MIT。

## 方法选择规则

1. 先写当前 unresolved decision，再选择方法。
2. 方法必须声明更新哪个案例对象；不能只输出一段听起来专业的话。
3. 一次只指定一个主方法，其他方法只作辅助镜片。
4. 已有方法覆盖时不注册同义方法。
5. 方法不能提升证据等级。`experience_judgment` 处理后仍不是客户事实。
6. 方法输出先进入 `DiagnosisStateV2`，再由 Presenter 决定可见内容。
7. 适用条件不满足时换方法或交付当前边界，不能要求用户为框架补材料。

## 私有方法与 Provider

私有判断通过 [../judgment-provider-contract.md](../judgment-provider-contract.md) 接入。Provider 只在最小生意图、议题和 selected focus 形成后查询；返回内容统一进入 `experience_judgment`，默认 `audiences: [consultant_only]` 或 `[internal_only]`。

只有同时满足 `confirmation_status: confirmed` 与 `lifecycle_status: current` 的记录可参与比较。零命中、过期、冲突和不可用不得阻断公共诊断，也不能替用户生成候选或选择焦点。

## 变更与废弃

- 修改方法含义时提升 version 并增加原始失败、相邻泛化和合法例外评测；
- 旧版 `public.business-six-lenses.v1`、`public.event-walkthrough.v1`、`public.hypothesis-fork.v1` 与 `public.dynamic-convergence.v1` 只作历史输入映射，新会话不再写入；
- 动态政策、市场数据、厂商排名和行业指标不进入方法注册表；
- 固定权重、成熟度阈值、周期和收益数字必须有独立事实源和计算验证。
