# 判断库检索契约

## 定位

判断库保存的是“面对某类情况时，狼哥如何取舍”的可复用判断。它为诊断提供优先级、关键变量和改判条件，不保存客户事实，也不能代替现场取证。

公开 Skill 只定义通用检索契约，不硬编码私人飞书 Base、table ID、账号、Token 或客户资料。私人或内部运行环境通过适配器提供数据。

## 权威与运行分层

推荐分成两层：

```text
权威编辑源（飞书 Base 或其他人工治理系统）
  → 单向同步、筛选、规范化、版本记录
运行时只读索引（应用数据库）
  → 诊断检索
  → 返回判断依据与版本
```

权威编辑源负责人工确认、修改、废弃和溯源。运行时索引只是可重建的派生数据，不提供人工编辑入口，也不反向覆盖权威源。

不推荐：

- 每个对话回合直接请求飞书：延迟、限流、授权过期和外部可用性会直接影响用户对话；
- 把 SQLite 或 JSON 快照提交进代码仓：容易和权威源漂移，无法安全处理多实例部署，也会把私人判断带入公开发布物；
- 把整张判断库塞进模型提示词：上下文噪音高，无法证明具体用了哪条判断。

已有 MySQL／PostgreSQL 的应用优先把只读索引放进现有数据库，不再引入 SQLite。数据量较小时先做结构化字段和关键词检索；记录规模和召回需求增长后，再增加向量或混合检索。

## 可检索记录

默认只索引同时满足以下条件的判断：

- 已经人工确认；
- 当前生效；
- 没有被替代或废弃；
- 具备适用场景、判断结论和至少一个关键变量或改判信号；
- 可以追溯到权威记录 ID 和版本。

“待校验”“待补充”“潜在冲突”“已被替代”“已废弃”默认不参与公开诊断。内部研究模式如需查看，必须显式开启并保持状态标识。

## 规范化字段

运行时记录至少包含：

```json
{
  "judgment_id": "stable-id",
  "title": "一句话判断",
  "applies_when": "面对什么情况",
  "decision": "狼哥怎么判断",
  "key_variables": ["变量 A", "变量 B"],
  "change_signals": ["出现什么情况应改判"],
  "suggested_actions": ["可选动作"],
  "business_scenes": ["企业 AI 提效"],
  "status": "confirmed",
  "version": "v1",
  "confirmed_at": "2026-01-01T00:00:00+08:00",
  "source_updated_at": "2026-01-01T00:00:00+08:00",
  "source_ref": "private-provider-ref",
  "content_hash": "sha256:..."
}
```

`source_ref` 可以是内部不可公开的定位键。对公众输出时只展示有权限公开的判断 ID、标题或摘要，不暴露私人链接。

## 查询输入

诊断引擎在两个节点查询：

1. 已经理解业务目标并形成候选假设后，用于选择最有价值的下一问；
2. 已经走查样本、准备比较候选起点时，用于检查优先级和改判条件。

查询结构示例：

```json
{
  "business_scenes": ["企业 AI 提效", "流程 AI 化改造"],
  "decision_question": "人工方法尚未稳定时，是否应该直接自动化",
  "observed_variables": ["当前结果依赖资深人员", "缺少书面标准"],
  "excluded_statuses": ["pending", "conflict", "superseded", "deprecated"],
  "limit": 5
}
```

不要把客户名称、个人信息、聊天全文、订单原文或敏感数据作为检索词发送回权威编辑源。优先使用脱敏后的业务场景、决策问题和关键变量。

## 返回与使用

提供方返回 0—5 条记录，并附同步状态：

```json
{
  "items": [],
  "index_revision": "source-revision",
  "synced_at": "2026-01-01T00:00:00+08:00",
  "stale": false
}
```

诊断引擎必须：

1. 先检查适用场景和关键变量，不只按标题相似度采用；
2. 同时读取改判信号，主动寻找反例；
3. 把判断写入内部“判断镜片”栏，不写入“客户事实”栏；
4. 最终候选能说明哪些判断影响了优先级；
5. 多条判断冲突时保留冲突，用客户样本和最新证据裁决；
6. 没有命中时继续诊断，不为了显示“有狼哥方法”强行套用。

## 同步与降级

推荐同步机制：

- 增量同步依据权威源更新时间、版本或 revision；
- 每次同步校验记录数、状态分布、必填字段和内容 hash；
- 定期做一次全量对账，发现删除或废弃时在运行索引中软禁用；
- 同步失败保留上一份可用索引，但标记 `stale` 和上次成功时间；
- 超过业务允许的新鲜度阈值后，不再把旧记录描述为“当前判断”。

判断库不可用或索引过期时：

- 公开诊断继续使用通用方法；
- 内部元数据记录未使用原因；
- 不把飞书错误、Token、接口或同步术语直接显示给普通用户；
- 不静默声称已经得到判断库支持。

## 安全边界

- 权威源凭证只在服务端同步任务使用，不进入浏览器、提示词、日志或公开仓；
- 应用运行时只读索引，不拥有修改权威源的权限；
- 客户对话数据与通用判断库分开存储；
- 公开 Skill 和应用发布包不包含私人判断正文的静态副本；
- 每次报告保存判断 ID、版本和索引 revision，便于后续重放和审计。
