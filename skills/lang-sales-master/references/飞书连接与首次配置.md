# 飞书连接与首次配置

本文件只定义销售大宗师如何调用飞书能力，以及学员首次安装后的连接流程。飞书登录、权限、妙记、纪要、云盘和文档的 API 细节由官方 `lark-*` Skills 负责；不要在本 Skill 中复制实现。

## 1. 能力与依赖

### 默认必需

- `lark-cli`：飞书命令行基础设施。
- `lark-shared`：配置、身份、授权、错误处理和安全约束。
- `lark-minutes`：搜索妙记、读取详情和导出逐字稿。

### 按需加载

- `lark-note`：妙记关联纪要、纪要详情和统一转写。
- `lark-drive`：按标题或关键词查找云文档，识别 Wiki 与云盘对象。
- `lark-doc`：读取已知云文档链接或 token 的正文。

不要把这些下游 Skills 复制进销售大宗师包。`lark-cli` 自带与当前版本同步的 Skill 正文，可用 `lark-cli skills read <skill-name>` 读取。

如果当前 AI 客户端没有注册 `lark-shared`、`lark-minutes` 等飞书 Skills，先说明会修改全局 Skills，取得用户确认后运行：

```bash
npx skills add larksuite/cli -g -y
```

注册完成后让用户新开任务或重启客户端，使 Skills 被重新发现。当前任务不能重启时，可以通过 `lark-cli skills read` 读取同版本内置规则完成流程。只有 CLI 版本过旧或内置 Skill 缺失时，才在用户确认后执行高风险写操作 `lark-cli update`。

## 2. 权限原则

飞书妙记是个人资源，默认使用用户身份，不能用机器人身份替代。初次连接只申请销售诊断所需的妙记只读权限：

```text
minutes:minutes:readonly
minutes:minutes.transcript:export
minutes:minutes.search:read
```

云文档、云盘和关联纪要权限在第一次真正需要时，按 `lark-doc`、`lark-drive`、`lark-note` 的要求增量申请。不要为了省一步而在初次配置时申请 `all`、妙记写入、消息发送、文档写入或客户资料写入权限。

## 3. 首次配置状态机

当用户说“连接飞书”“刚安装好”“第一次用妙记”或飞书读取失败时：

1. 运行 `scripts/feishu_preflight.sh`。
2. 根据输出只处理当前缺口：
   - `NODE_INSTALLED=0` 或 `NPM_INSTALLED=0`：说明需要 Node.js/npm，停止自动安装并请用户先完成运行环境安装。
   - `LARK_CLI_INSTALLED=0`：说明将进行全局安装，用户确认后运行 `npm install -g @larksuite/cli`。
   - `LARK_SHARED_BUNDLED=0` 或 `LARK_MINUTES_BUNDLED=0`：当前 CLI 的内置 Skill 不完整，用户确认后更新 CLI。
   - `LARK_CONFIG_READY=0`：进入“创建或绑定飞书应用”。
   - `USER_AUTH_READY=0`：进入“用户身份授权”。
   - `MINUTES_SCOPES_READY=0`：只补齐缺失的妙记只读权限。
   - 全部为 `1`：执行只读连通性检查。

预检结果只表示环境状态，不得回显完整授权状态 JSON，因为其中可能含姓名、open_id、权限列表和其他账户信息。

预检脚本只能确认 CLI 是否自带规则；当前 AI 客户端是否已经注册这些 Skills，由运行时的可用 Skills 列表判断。未注册时按第 1 节安装，并在客户端刷新后继续。

## 4. 创建或绑定飞书应用

先完整读取 `lark-shared`，再根据运行环境选择路径。

### 普通桌面客户端

1. 在后台启动 `lark-cli config init --new`，不要阻塞等待。
2. 从运行输出中取得当次验证 URL。
3. 使用 `lark-cli auth qrcode <验证URL> --output <相对路径.png>` 生成二维码。
4. 同时向用户展示可点击链接和二维码，说明要在飞书开发者页面完成应用创建与权限确认。
5. 用户确认完成后再继续检查配置状态。

### OpenClaw、Hermes 或已有飞书 Channel 的环境

不要自动新建或覆盖现有配置。先向用户确认是否绑定当前飞书应用；读取个人妙记必须绑定 `user-default`，`bot-only` 无法读取个人妙记。只有用户确认后才执行 `lark-cli config bind`。

任何路径都不得显示或保存 App Secret，不得把用户账户配置写进销售大宗师目录或分发包。

## 5. 用户身份授权

1. 读取 `lark-shared` 的授权规则。
2. 使用以下最小权限发起非阻塞授权：

```bash
lark-cli auth login --scope "minutes:minutes:readonly minutes:minutes.transcript:export minutes:minutes.search:read" --no-wait --json
```

3. 使用当次返回的验证 URL 生成二维码，同时提供可点击链接。
4. 当前轮结束，等待用户在飞书完成授权。
5. 用户确认后，使用本次新生成且尚未持久化的 `device_code` 完成登录，再运行预检。

验证 URL 和 `device_code` 只属于这一次授权流程：不写文件、不写报告、不长期保存、不复用历史值。链接失效或流程中断时，重新发起授权。

## 6. 连通性检查

授权完成后运行：

```bash
bash scripts/feishu_preflight.sh --live
```

脚本会执行一个当天范围、最多一条结果的妙记只读搜索并丢弃业务数据。搜索为空但命令成功，仍表示连接正常；只有命令或权限失败才表示连通性异常。

如果用户已经给出一条妙记链接，优先用这条链接做实际验证：从 URL 提取 minute token，按 `lark-minutes` 的详情流程请求 `--transcript`。不得用飞书 AI 总结代替逐字稿测试。

## 7. 妙记读取路由

### 用户给出妙记链接

1. 从 `/minutes/<token>` 路径提取 minute token。
2. 读取 `lark-minutes` 及其详情参考文件。
3. 使用用户身份读取详情，并显式请求逐字稿。
4. 只把逐字稿和必要元数据交给销售诊断流程。

### 用户要求搜索妙记

1. 读取 `lark-minutes` 及其搜索参考文件。
2. 搜索必须至少有一个过滤条件：关键词、时间、所有者或参与者。
3. “我的妙记”默认按所有者 `me`；“我参与的妙记”需要合并所有者 `me` 与参与者 `me` 的结果并去重。
4. 单次搜索时间范围不得超过一个月；更长范围按月拆分。
5. 候选结果较少时让用户选择；用户已给出明确标题、时间或链接时直接读取。
6. 超过 50 条时先汇报数量、日期范围与筛选条件，得到用户确认后再批量读取逐字稿。

### 关联纪要或云文档

- 妙记详情返回 `note_id` 且用户需要纪要时，切换到 `lark-note`。
- 用户给出文档链接或 token 时，切换到 `lark-doc`。
- 用户只提供自然语言标题、关键词或 Wiki 链接时，先用 `lark-drive` 查找或识别对象，再切换到 `lark-doc` 读取正文。

## 8. 证据、安全与写入边界

- 销售判断以逐字稿、客户原话、具体动作、时间和数字为证据。
- 飞书 AI 总结、章节、关键词和待办只作导航；引用时必须回到逐字稿。
- 保留妙记标题或 token、说话人原始标签和时间戳；说话人不明确时不猜身份。
- 默认只读，不改妙记标题、不改纪要、不创建任务、不写文档、不更新客户档案。
- 用户明确要求写入时，先确认目标、字段、权限和敏感信息，再切换到对应下游 Skill；销售大宗师本身不实现写入。
- 输出和日志不包含 App Secret、访问令牌、刷新令牌、授权码、验证 URL 或 `device_code`。
