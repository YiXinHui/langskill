# 2026-07-30 企业 AI 初诊先理解业务再判断问题

## 给非技术读者的一句话

企业 AI 初诊不再因为用户说“销售”“短视频”或“人效低”就猜问题，而是先弄清公司做什么、卖什么、客户是谁，再用真实事件验证判断。

## 这次做了什么

- 把初诊主流程调整为“角色范围 → 公司业务 → 产品／服务 → 典型客户 → 正常流程 → 问题确认 → 近期事件 → 证据走查”。
- 增加业务背景、用户陈述、当前假设、已否定／已纠正四栏事实账本。
- 明确职责、行业、渠道和工具只是范围信息，不能自动升级为漏跟、返工或低效事实。
- 用户说“都不符合”“没有漏跟”时保留纠正，不再换一种说法继续追同一假设。
- 将“一次一个问题”收紧为“一轮只收一个事实”，并修正口述事件的证据措辞。
- 参考麦肯锡公开的结构化问题、事实基础和假设验证原则，裁剪为 5 分钟公开初诊流程。
- 新增 6 条回归场景，并更新既有宽泛“人效低”和无主题首问场景，共形成 15 条公开 eval。
- 版本从 `0.9.1` 升级为 `0.9.2`。

## 为什么要做

- 生产试用录屏显示，旧版在不了解行业、产品、客户和正常业务过程时就直接追问漏跟细节，不符合基础商业咨询顺序。
- “销售”“短视频加微信”只说明职责和渠道；把它们写成“已有客户漏跟”会制造事实，后续所有追问都会被错误前提带偏。
- 真实事件应该用于验证假设，不应该替代理解客户业务本身。

## 对系统意味着什么

- 首屏先让用户选择自己熟悉的角色／工作范围，不要求用户先认领公司问题。
- 后续逐轮补公司业务、产品／服务和典型客户；用户已提供的信息不会机械重问。
- 明确问题仍可直接进入近期事件，不会因为新增背景门槛而变成固定问卷。
- 应用层后续只封装结构化选项和卡片展示，不承担第二套诊断逻辑。

## 怎么证明没搞坏

```bash
python3 -m json.tool skills/lang-enterprise-ai-diagnosis/evals/evals.json
node scripts/validate-sharing-system.mjs
./pre-check.sh
git diff --check
```

行为验证：

- 10 个候选版全新模型回合；
- 10 个 `0.9.1` 旧版快照对照回合；
- 候选版通过 `31 / 31` 项断言，旧版通过 `17 / 31`；
- 第 0 问从症状菜单改成角色范围后，使用全新只读模型回合定向重跑并通过 3 / 3 项首问断言；未受该入口改动影响的其余 9 个场景沿用同一候选版本的隔离回合；
- 通用 Skill 评审页和聚合 benchmark 已生成于本地忽略工作区。

## 还没解决什么

- 应用层动态选择卡片已在独立应用分支完成封装和自动化验证，尚未合并、部署或完成生产 Web／小程序人工验收。
- 尚未在三个不同行业的真实匿名初诊中验证完成率和问题命中率。
- 这仍是公开自述初筛，不替代正式企业诊断取证。
