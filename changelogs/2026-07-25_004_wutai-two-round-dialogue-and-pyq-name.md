# 2026-07-25 五台山升级为双巡论道，朋友圈入口改为 lang-wechat-pyq

## 给非技术读者的一句话

五台山论道不再是几个人轮流发表看法，而是先立论、再互相回应的双巡交锋；朋友圈 Skill 也按最终命名改为 `lang-wechat-pyq`。

## 这次做了什么

- 将朋友圈公开入口从 `lang-wechat-moments` 修正为 `lang-wechat-pyq`。
- 重写五台山论道的完整机制，形成“定题、排席、各自立论、对席追问、山主收束”五关。
- 增加第二巡回应、人物思想真实性边界和现代议题推演回归场景。
- 在发布检查中加入五台山独立结构与来源痕迹检查。

## 为什么要做

- `pyq` 是用户确认的最终命名，继续保留 `moments` 会让公开入口与个人习惯不一致。
- 旧版五台山的流程过于接近常见的多角色发言工具，人物之间没有真正读取和回应对方观点。
- 历史人物讨论现代问题时，必须区分思想推演与本人原话，避免为了戏剧性编造事实。

## 具体改了什么

| 文件/模块 | 改动 | 你需要知道的意思 |
|---|---|---|
| `skills/lang-wechat-pyq/` | 原 `lang-wechat-moments` 改名 | 当前朋友圈调用入口为 `/lang-wechat-pyq` |
| `skill-renames.json` | 旧中文名和 `lang-wechat-moments` 都指向新名 | 已安装用户升级时会自动清理旧目录 |
| `skills/lang-wutai-dialogue/SKILL.md` | 建立五关与双巡交锋 | 人物不仅各自立论，还必须回应对方真实主张 |
| `skills/lang-wutai-dialogue/evals/evals.json` | 更新 3 个既有场景并新增现代议题边界测试 | 防止退回单轮发言、虚假交锋或伪造历史人物原话 |
| `scripts/validate-sharing-system.mjs` | 增加独立阶段和外部来源痕迹门禁 | 当前公开文件重新出现相关痕迹时发布检查会失败 |
| `README.md`、`skill-catalog.json`、`VERSION` | 同步入口、清单与 `0.6.1` 版本 | 用户文档、机器配置和升级检测保持一致 |

## 对系统意味着什么

- 五台山的最小完整体验变成“两巡”：第一巡守住各自命题，第二巡针对对方实际观点交锋。
- 山主不再强行总结共识，而是区分事实模型、价值排序和承担代价的差异。
- 对历史人物只做有依据、有边界的思想推演，不伪装成真实引语。

## 怎么证明没搞坏

```bash
node scripts/validate-sharing-system.mjs
./pre-check.sh
git diff --check
node -e '/* 解析清单、迁移表和 eval JSON */'
node -e '/* 对比新版与本机参照文件的非平凡完全相同行 */'
```

结果：

- `7` 个公开 Skill 通过目录、frontmatter 和清单一致性检查。
- 五台山五个独立阶段均存在，公开 Skill 与 eval 中的来源痕迹为 `0`。
- 新版五台山与参照文件的非平凡完全相同行为 `0`；旧版为 `3`。
- `3` 份关键 JSON 可解析，敏感信息扫描为 `0` 条，`git diff --check` 通过。

## 还没解决什么

- 双巡交锋的真实模型表现仍需结合后续用户使用继续观察，尤其是第二巡是否真的回应对方而不是改写自己第一轮。

## 技术细节

- 名称迁移：`狼哥朋友圈`、`lang-wechat-moments` → `lang-wechat-pyq`。
- 五台山静态门禁同时校验五关存在与外部来源标识缺失。
