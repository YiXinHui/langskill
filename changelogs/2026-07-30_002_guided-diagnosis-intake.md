# 2026-07-30 企业 AI 初诊改为低门槛分流

## 给非技术读者的一句话

企业老板不再需要一上来就讲完整案例：先选一个熟悉的业务现象，再从一个小事实慢慢进入真实事件。

## 这次做了什么

- 把企业 AI 初诊的默认首问拆成“第 0 轮业务分流 → 第 1 轮小事实 → 第 2 轮真实事件”。
- 删除默认的“关键员工明天不来会停什么”假设，避免在还没理解企业前就把问题带向人员单点依赖。
- 为“不知道怎么回答”增加明确降级规则：不重复原问题，改用过去一周常见话语或现象做选择题，并始终允许“说不清”。
- 增加三个回归场景，覆盖无主题进入、回答困难和用户已经提供具体业务问题时跳过菜单。
- 将公开方法版本从 `0.9.0` 调整为 `0.9.1`。

## 为什么要做

- 真实试用中，用户面对开放式“请举一个近期真实案例”时不知道从哪里讲起，补救回复仍然要求一次组织完整故事。
- 结构化问题拆解应由诊断方完成。用户只需要识别自己见过的现象，不应该先学会咨询表达才能获得咨询帮助。
- 原默认问题把“关键员工依赖”当作起点，存在先入为主风险，也可能漏掉销售、交付、运营、后台协同和经营数据中的断点。

## 具体改了什么

| 文件／模块 | 改动 | 你需要知道的意思 |
|---|---|---|
| `skills/lang-enterprise-ai-diagnosis/SKILL.md` | 重写首轮原则、默认第 0 问和“不知道”降级路径 | 用户可以只回一个数字开始诊断 |
| `references/conversation-guide.md` | 增加分流、定位、事件、走查四级漏斗和按业务方向的小事实示例 | AI 负责拆问题，不把完整问卷一次交给用户 |
| `evals/evals.json`、`evals/2026-07-30_guided-intake_smoke-results.md` | 增加三条真实反馈回归和三次新鲜模型烟测 | 以后更新不能把抽象首问悄悄带回来 |
| `docs/DESIGN.md` | 明确有主题时跳过菜单、无主题时逐步收窄 | 选择题是导航，不是固定问卷或诊断结论 |

## 对系统意味着什么

- 对话接口、报告结构、权限和数据边界均未改变，属于可由应用后台直接准备的普通方法更新。
- 新规则只影响使用新 Skill 版本发起的后续模型请求，不会改写历史会话。
- 当前生产版本在应用侧获得明确上线授权前不会自动切换。

## 怎么证明没搞坏

完成修改后运行：

```bash
python3 -m json.tool skills/lang-enterprise-ai-diagnosis/evals/evals.json
node scripts/validate-sharing-system.mjs
./pre-check.sh
git diff --check
```

结果：

- 企业初诊结构检查：`3 references, 9 evals`，通过；
- 公开仓分享系统：`14 public skills`，结构检查通过；
- 发布前敏感词扫描、JSON 语法和 `git diff --check`：通过；
- 三个全新模型回合全部符合预期：无主题时给业务现象分流、“不知道”时继续降级、具体销售问题时跳过总菜单。行为证据见 `skills/lang-enterprise-ai-diagnosis/evals/2026-07-30_guided-intake_smoke-results.md`。

## 还没解决什么

- 还需要在真实应用新会话中验证首轮选择率、从选择到真实事件的完成率，以及不同行业是否需要调整现象措辞。
- 本次不新增自动提交联系方式、客户系统写入或正式诊断权限。
