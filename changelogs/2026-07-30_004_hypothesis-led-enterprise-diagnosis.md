# 2026-07-30 企业 AI 初诊改为假设驱动咨询

## 给非技术读者的一句话

企业 AI 初诊不再像问卷一样逐项盘普通流程，而是先形成商业判断，再用真实样本和反例检验 AI 应该从哪里开始。

## 这次做了什么

- 用两类匿名真实售前咨询模式重构初诊方法：专家服务难复制，以及多业务并行与扩张。
- 将“一次只问一个问题”改为“一回合推进一个判断”，普通订单起点、打单、发货和完成状态不再默认逐项询问。
- 增加客户选择、价值链位置、增长上限、专家依赖、行为摩擦、更新反馈六类战略切面。
- 真实样本改为检验已形成假设的手段，不再作为用户尚不知道讨论什么时的开场作业。
- 新增判断库检索契约，明确飞书等人工治理系统是权威源，应用数据库保存单向同步的只读运行索引。
- 把报告改为“业务价值 → 工作假设与改判信号 → 样本验证 → 候选起点 → 最小闭环”。
- 版本从 `0.9.2` 升级为 `0.9.3`。

## 为什么要做

- 真实试用截图显示，旧版已经知道公司做五金品牌电商后，仍连续询问正常订单从哪里开始、由谁处理、何时完成。这些答案只是行业常识，既不改变候选方向，也不能体现咨询专业性。
- 真实售前咨询的高价值转折来自战略判断和现场验证：先判断客户为什么需要这家公司、什么能力限制增长，再用真实输入、对照或边界案例找出数据、规则、隐性经验、交互和组织问题。
- 私有判断库如果每轮直接请求飞书，会把外部延迟、授权和可用性带进用户对话；把 SQLite 或 JSON 提交到公开代码又会造成漂移和隐私风险。

## 对系统意味着什么

- 无主题用户先用产品、服务、客户和想改变的结果自然开场，不先选角色或症状。
- 业务背景足够后，AI 必须提出可被用户纠正的当前假设，并选择能改判的问题或样本。
- 发现错误时先区分输入、规则、隐性经验、数据结构、交互、组织和风险，不默认补提示词或推荐智能体。
- 判断库采用“权威编辑源 → 单向同步 → 应用只读索引”；已有 MySQL 的应用不再额外引入 SQLite。
- 当前仍只修改上游公开 Skill；应用层封装和生产发布要等沙盒人工复测通过后再做。

结构与发布校验：

```bash
python3 -m json.tool skills/lang-enterprise-ai-diagnosis/evals/evals.json
git diff --check
./pre-check.sh
node scripts/validate-sharing-system.mjs
```

结果：JSON、补丁空白、敏感词预扫描和 14 个公开 Skill 结构校验均通过。

行为验证：

- 运行 9 个互不共享上下文的新鲜模型回合，覆盖 7 个不同场景并定向重跑 2 个判断库场景；所覆盖断言均符合预期。
- `0.9.3` 本地沙盒完成五金电商与判断库礼赠场景的真实多轮连通验证。
- 使用官方 Skill 评审工具生成 7 个场景的人工评审页。

## 还没解决什么

- 判断库目前只定义通用契约；应用侧 MySQL 表、飞书增量同步任务和检索适配器尚未实现。
- 沙盒只加载三条已确认判断的临时只读索引，不等于生产判断库已经接通。
- 尚未完成跨行业真实用户完成率、正式诊断准确率、Web 应用封装或生产发布验收。
