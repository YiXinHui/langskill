# 2026-07-25 公开核心与内部增强联动

## 给非技术读者的一句话

langskill 从“公开 Skill 集合”升级为可被私人和内部版本稳定复用的公开上游，避免同一能力维护两份。

## 这次做了什么

- 建立公开 Skill 机器清单和校验脚本。
- 新增公开核心 `lang-skill-feedback`。
- 明确“内部孵化、通用化后晋升为公开上游”的分享规则。
- 补齐公开仓设计文档、待办和发布边界。

## 为什么要做

以前公开版被理解为内部版的手工精简副本，长期会产生版本漂移，也容易在脱敏时遗漏信息。现在公开核心拥有唯一真身，内部只叠加自己的规则和配置。

## 具体改了什么

| 文件/模块 | 改动 | 你需要知道的意思 |
|---|---|---|
| `skills/lang-skill-feedback/` | 新增反馈学习公共核心与测试 | 任何团队都能复用，不含私人配置 |
| `skill-catalog.json` | 新增公开 Skill 清单 | 仓库可以机器检查遗漏和角色 |
| `scripts/validate-sharing-system.mjs` | 新增结构校验 | 新增 Skill 后不再只靠人工记 README |
| `docs/DESIGN.md` | 固化公开上游边界 | 内部版不能复制公开核心分别维护 |
| `VERSION` | `0.4.0` 升至 `0.5.0` | 新增公开 Skill，按 minor 发布 |

## 对系统意味着什么

- 通用改动今后先进入 langskill，再由内部版升级依赖。
- 内部业务变化不会污染公开核心。
- 公开仓可以独立接收 issue、修复和外部贡献。

## 怎么证明没搞坏

待实现完成后运行：

```bash
node scripts/validate-sharing-system.mjs
./pre-check.sh
```

结果：

- `7` 个公开 Skill 全部进入机器清单并通过结构检查。
- `pre-check.sh` 扫描结果为 `0` 条内部业务残留。
- `lang-skill-feedback` 的 JSON 测试集通过语法检查。

## 还没解决什么

- `v0.5.0` 尚未推送到 GitHub；内部远程安装在发布 tag 前仍使用本地源验证。
- 其他内部 Skill 只完成分类，尚未批量拆分迁移。
